# 用 Accio 整理商品资料与双语文案

适用：已由元衡配置并受控启动的 Accio。这里使用本地文件工具，不依赖官方电商云端连接器，也不会自动上架商品。生成会产生模型用量，正式使用前请先做小样本核对。

## 第一次怎么用

1. 新建一个专门的商品工作文件夹，先放两三条不含个人信息的资料。可从[样例目录](../examples/accio-commerce)复制 `products.json` 和 `task.md`，先跑一遍演示。
2. 在元衡选择支持的模型和分组，从元衡启动 Accio。进入 Accio 后选择这个工作文件夹。
3. 在输入框发送：

   > 请读取当前工作文件夹的 task.md 和 products.json，按任务说明整理中英文商品文案，保存为 listing-draft.json 和 listing-draft.md，并读回核对。不要访问网络、其他文件夹或发布到店铺。

4. 遇到文件写入审批，检查路径是否为这个工作文件夹，再允许本次操作。不要为了省事关闭全局审批。
5. 打开 `listing-draft.md` 审阅中英文标题、卖点和待补信息，再核对 `listing-draft.json` 里的 SKU、价格、材质和尺寸。模型说“已完成”不代表文件一定存在或信息一定准确。

## 修改某个商品

继续在同一会话发送，例如：

> 只把 DEMO-BAG-01 的英文标题改为 Canvas Organizer Bag for Daily Storage，并同步 Markdown 预览；其他字段和第二个商品保持不变。读回两个文件核对后再回复。

不要让模型猜缺失的防水、承重、认证信息。未知项应列为“待确认”，而不是写成已经认证或确定没有。价格、尺寸与功能最终以真实商品资料为准；草稿不能视为平台审核或法律合规证明。

## 检查与恢复

维护者可用 `node scripts/check-accio-commerce.mjs <工作文件夹>` 核对格式、SKU、价格和双语预览一致性。该检查不访问网络，也不能代替人工事实审稿。

退出前保存文件；再次使用时先从元衡启动 Accio，再核对模型菜单、分组和工作目录。普通打开官方应用不能证明已走元衡。若任务失败，先保留诊断编号和当前文件，不连续重复提交；只读、模型生成、文件写入和官方云端业务是不同环节。

## 已验证范围

Accio 0.37.1、Apple Silicon Mac 专用测试环境、元衡 Astra：两条商品资料生成双语JSON/Markdown并读回通过；只改一个商品标题的修订通过，其他字段和另一商品不变。退出并受控重开应用后，同一会话的显式模型选择和元衡配置保留。此结果不代表整机重启、Accio升级、其他模型或系统均已验证，也不代表官方店铺搜索、采购、支付或上架功能已经接入。
