# Claude Desktop Windows 首次使用准备

此流程把 Windows 必要组件准备接入元衡的安装、配置和启动入口，不代表默认执行了模型推理。

## 用户流程

1. 在元衡工具管理中点击“安装并准备 Claude Desktop”。已安装用户点击配置或启动也会检查。
2. 元衡检查虚拟机平台、虚拟化运行状态和系统虚拟化服务。缺少必要组件时说明操作范围，由用户确认一次，再弹出 Windows 管理员授权。
3. 仅使用 Windows 自带 DISM 启用 VirtualMachinePlatform 及其依赖；不修改 BIOS、防火墙、代理或回环规则，不调用模型。
4. 系统组件可能需要重启。保存工作后由用户手动重启，元衡不会自动重启。已经提交的模型/分组配置保留；恢复标记不保存账号或密钥。
5. 重启后重新打开元衡，自动恢复只读检查。基础环境就绪后点击“继续安装或配置 Claude”，回到工具管理继续官方下载安装或启动现有应用。
6. Claude 自己的工作区运行文件下载、网关认证和真实模型请求是另外的阶段。网络不可达时仍须处理官方下载问题，不能把 Windows 功能已开启视为完整可用。

## 不再自动提醒

如果准备失败或暂时不使用 Claude，可勾选环境提示下方的“不再提醒”，再点击“稍后处理”。偏好立即保存在本机，之后重新进入元衡不会自动弹出准备提示，也不会显示闲置的“继续准备 Claude”按钮。

需要时仍可在工具管理中安装或配置 Claude，主动操作会重新检查环境；重试不会清除“不再提醒”的选择。若要恢复启动提醒，可在再次出现的环境提示中取消勾选。偏好不随账号同步到其他设备，清理客户端本地存储后会恢复默认；保存失败时会明确提示重试。

## 操作保护

- 不同入口共享一次准备任务；取消管理员授权不会自动重试。
- Windows servicing 无安全强杀语义；界面可收起，最多自动等待十分钟，超时不终止系统安装。重新检查确认结果后继续。
- 应用退出时不终止 DISM。恢复时若上一任务结果未知，禁止重复提交，提示先确认系统安装窗口结束后再重启。
- 明确的准备成功退出码先记为需要重启，再以新的系统启动时间和实际功能状态确认就绪；未知/无权限不能当成未启用。
- 配置已经保存但环境需重启时，以“配置已保存，环境待准备”提示，不将已保存的模型选择回退或谎报配置失败。
- 安装观察停止或页面卸载后，迟到的准备结果不会自动打开下载页；停止观察不是取消 Windows 系统安装。

## 验收边界

自动测试使用合成数据和模拟 IPC；没有在开发 Mac 上执行 Windows 组件启用或收费请求。Windows 专用 Rust 代码做隔离目标平台类型检查，配置存储边界使用 stub，不等同完整 Windows 客户端构建或实际 UAC 验收。

Windows 真机验收应包括：全新用户、已安装但缺组件、UAC 拒绝、功能启用后待重启、重启后继续、应用在准备时退出、系统受管/查询未知、固件虚拟化未启用、下载网络失败和原有 GPT 不受影响。不要为了通过测试关闭防火墙或批量杀死系统安装进程。
