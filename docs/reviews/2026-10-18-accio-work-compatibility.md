# Accio Work 本地兼容性验证与接入方案

验证日期：2026-10-18 至 2026-10-19。状态：本地实验原型已完成 Mac ARM 官方 0.34.5 主模型链路，以及元衡 GUI 路径选择、分组配置、启动和真实回复；发布前发现的孤立能力令牌和连接器重试回路已在本地修复并补测。下载安装/更新、云端扩展及其他系统尚未验收。未提交、发布，默认关闭。

## 结论

本地原型增加 Accio 独立运行时配置、分组目录、受限 Core 路由、Responses 中间协议转换及 Mac 官方签名/版本启动检查；前端入口与后端路由均默认关闭，需要明确开启实验开关。纯本地测试覆盖 Responses、Chat Completions、Anthropic 三条 HTTP 往返；10 月 19 日实际 Core 与 Mac ARM 官方 0.34.5 完成会话恢复、两种元衡模型原生切换、多轮、文件工具往返与取消，未修改原 Codex 配置。当前放行两个模型端点与四个固定官方身份端点，云端工具/媒体/嵌入等未知路径仍拒绝。

原版主聊天使用 Accio 网关协议和会话令牌，不能直接写入标准 OpenAI Base URL。主模型桥接和元衡 GUI 对已有官方应用的配置/启动已得到实测；下载安装/更新、Windows、Intel 和完整云端工作流仍未验收。分阶段结果见下，最新结论以 10 月 19 日 GUI 验收节为准。

## 来源与身份

- 来源：官网 `https://www.accio.com/work` 及其明确提供的三个下载入口；Mac ARM 入口 `https://www.accio.com/work/fixed/download?platform=macAppleDownloadUrl` 重定向到 `work-download.accio.com`。
- 本地测试版本 0.34.5，Mac ARM PKG 大小 247595020 字节，SHA-256 `88ea9a2ac6b3d7d579b4709ac5b43223e4a8a9ff4ced1b00d13e6e2b45989e9b`。
- `pkgutil --check-signature` 确认 Apple 分发签名且公证可信。应用 `codesign --verify --deep --strict` 通过。
- 应用名 Accio.app，Bundle ID `com.accio.desktop`，Team ID `P75YXKHHMH`，签名主体 ALIBABA.COM GLOBAL E- COMMERCE PTE. LTD.。
- PKG 目标 `/Applications`，需要系统 Installer 授权。官网也提供 Intel PKG 和 Windows EXE，但本轮未下载和运行这两个版本，不能推断它们的签名身份和实机结果。

## 本地验证方法与结果

第一阶段仅解包官方 PKG 和 ASAR 到临时目录，未执行 preinstall/postinstall，未写实际用户 `.accio`、模型配置或官方登录材料。针对已验证的官方 `gateway-worker.js`，抽取原始函数/类并在隔离 JavaScript 上下文执行。模型目录使用随机端口 loopback 模拟服务器；模型构造及 transport 使用桩依赖，在联网前截获请求。只用假令牌、假模型名；没有实际元衡或 Accio 推理请求。

可复现脚本：`node scripts/test-accio-work-protocol.cjs <gateway-worker.js>`。脚本锁定该版本源码 SHA-256 `b42bb8d4c524600d78592a1cdf1c4472e961fa1ae3144f23f3f41bf14db8853d`，不能把新版不匹配当作兼容。厂商包本身不纳入仓库。

6 项通过：

1. 模型目录函数不读取 `OPENAI_BASE_URL` / `OPENAI_API_KEY`；试图访问非 loopback 目标时测试拦截器拒绝，未发外网请求。
2. 指向标准 `/v1` 后实际请求是 `POST /v1/llm/config/v2`，模拟标准服务返回 404；不是 `GET /v1/models`。请求体携带 Accio 会话 token，没有 OpenAI Bearer 认证头。
3. 厂商格式目录模拟端点返回成功，验证不是测试器统一失败；区域头按参数传递。
4. HTTP 200、业务 `LOGIN_REQUIRED` 被原函数识别为失败，不将传输成功当成业务成功。
5. 官方模型构造器接受 gateway 地址，但不会因此读取 OpenAI 环境变量；模型请求采用 `contents` 等字段而非 `messages`。
6. 官方 transport 在请求拦截点生成 `.../api/adk/llm/generateContent?sg_k=...` 和 SSE Accept；未发送真实请求。序列化、签名等依赖使用桩，这项仅证明路由及请求边界，不证明可完整模拟网关或模型推理成功。

静态交叉检查：桌面模型目录调用方显式传入官方网关地址；`GATEWAY_BASE_URL` 修改的是通用网关，而非独立第三方模型服务商配置。包内 OpenAI SDK 出现在工具依赖中，不足以证明主聊天支持自定义模型。检索配置、主进程、worker 与设置界面包，未确认支持用户 Base URL/API Key 的公开主模型入口；这是未发现，不是证明任何版本永远不支持。

## 隐私观察

官方 preinstall 将硬件 UUID 的 SHA-256 作为设备标识上报；postinstall 的安装完成事件包含 `computer_name`（来自系统电脑名称）。电脑名称可能包含姓名。脚本还读取本机用户名来定位用户目录，但此处没有证据证明用户名字段被直接上报。两阶段均未执行安装脚本，未触发这些安装上报。第二阶段正常运行确认了公网 IP/地区检测和设备识别初始化，但未做全流量审计，不能声称运行时没有其他遥测，也不能将安装脚本的电脑名称字段当作运行阶段已上传的证据。已向用户说明正常运行可能产生设备遥测；不记录真实 IP、电脑名称或设备标识到本报告。

## 第二阶段：原版 App 运行验证

用户进一步要求实际运行后，确认本机没有既有 Accio 数据目录。建立临时空目录，仅在原路径不存在时创建指向临时目录的链接，拒绝覆盖原数据；Electron user-data-dir 同样指向临时位置。官方签名 App 本体保持不变，未执行安装器。

离线沙箱先做有效性检查和外网拒绝检查，原版进程启动后遇到 macOS sandbox extension 限制，未取得窗口；这是测试包装方式限制，不作为产品失败。随后在已向用户说明运行遥测的情况下正常启动原版。观察结果：

- 原版 v0.34.5 启动成功，原生可访问性树显示 Accio Work 登录页及“登录即可每日解锁免费额度”“登录”按钮。
- 原生应用菜单只有关于、检查更新、隐藏、退出，未登录页面没有自定义模型入口；不据此推断登录后绝无此能力。
- 本地网关启动并通过自身健康探测，状态 `authenticated=false`。日志明确说明 WebSocket 和资源在官方登录后初始化。
- 公网心跳/地区探测和域名配置请求成功，设备识别组件初始化。未提交任何登录信息、个人文件、元衡 API Key 或推理请求。
- 测试进程组已停止，Accio/Helper/crashpad 进程为零，本轮网关监听已关闭；三个临时数据链接已移除，原路径恢复为不存在。临时运行日志不提交 Git。

## 第三阶段：登录后端到端最小验证

用户在临时数据环境中完成官方账号登录后，继续做只读界面检查和一轮不含个人信息的测试请求：

- 新任务的模型选择器可打开，显示“自动”、标准/专业/极致以及多个可用模型；其中包含 `DeepSeek V4.1 Flash`、Qwen、GLM、Kimi 等型号。
- 选择 `DeepSeek V4.1 Flash` 后，输入 `Reply with exactly ACCIO_TEST_OK. Do not use any tools or read files.`，返回完全匹配的 `ACCIO_TEST_OK`。日志记录模型调用约 2.49 秒、端到端消息约 3.26 秒，界面时间戳相差约 4 秒；传输状态为 HTTP 200，模型工具调用数为 0，结束原因为正常停止。用量记录为输入 37,081 tokens、输出 6 tokens，说明短提示仍附带了较大的系统/工具上下文，不应承诺低消耗。
- 这次请求使用 Accio 官方网关和 Accio 自有模型目录/会话协议；没有走 OpenAI `/v1/models`、`/v1/chat/completions` 或 `/v1/responses`，也没有读取元衡 Base URL/API Key。
- 登录后的偏好/系统页面仍未发现自定义供应商、Base URL、API Key 或第三方模型网关入口。因此当前只能确认“官方账号 + 官方模型可用”，不能确认“元衡模型可用”。

隐私边界补充：本地运行日志显示模型请求上下文包含本机用户目录下的多个绝对路径，以及文件/工作区上下文提示。日志不足以确认实际文件正文是否一并发送，因此不能声称“只发路径，未发文件内容”。我们发送的单轮测试调用本身工具调用数为 0；同一运行期间另观察到 Accio 发起设计编辑器相关的 MCP 工具调用及资源读取，未能确认触发源与测试提示词有关。向用户披露该情况后，已退出应用并清理隔离测试数据。

## 前期可执行方案（主模型方向已由实验原型替代）

### 第一阶段：官方账号工具接入

复用元衡的工具目录、桌面应用检测、安装观察、取消/超时、缓存与启动路径，不复制 WorkBuddy 的模型配置写入器。

1. 在 `YuanhengToolId`、工具目录和标签中增加 `accio-work`，引入“官方账号 / 不支持元衡模型配置”的能力标记。工具管理与工作台都应按能力隐藏元衡模型/分组配置按钮；禁止把启动成功显示成“元衡配置成功”。
2. macOS 区分 ARM64/Intel，下载入口采用官网可验证的动态重定向，所有跳转限定官方域名、HTTPS；验证 PKG 与 App 的实际签名和身份。不得直接复用元衡自身 R2/GitHub 下载候选，它们不是 Accio 的官方下载源。
3. 用户确认后打开系统安装器，观察安装结果，支持重新检测和手动选择路径；取消/失败不写已安装标记。检测优先 Bundle ID/签名，再核验可执行文件；不按同名文件直接信任。
4. Windows 按实际官方包验证 Authenticode 发布者，检查注册表、常见安装路径和自选路径；WindowsApps 情况走正确的应用激活机制，不能假设普通 EXE。发布 Windows 支持前必须实机验收。
5. 启动原版 App，引导用户自行登录 Accio 官方账号。元衡不复制官方 token，不写 GATEWAY_BASE_URL，也不将元衡密钥传给 Accio。
6. 状态区分：未安装、等待安装、已安装可启动、签名/路径异常。未接入官方登录状态接口时不要声称“已登录”，应用能启动也不代表能对话。

### 第二阶段：元衡模型适配的准入条件

优先取得 Accio 官方支持的 BYOK/自定义模型入口、配置结构及许可说明。得到后，验证读取→备份→写入→回读→撤销，覆盖模型目录、单轮、流式、多轮、工具调用、取消、鉴权失败和更新后保留配置；分别在 Mac 和 Windows 实机验收。

如果官方确认没有这种能力，协议转换不是“一键加个地址”：还需独立验证官方登录如何保留、模型目录协议、签名/令牌、流事件、工具调用、用量和取消语义，以及其他服务请求不受影响。目前没有证据证明完整可行，不能纳入本阶段交付承诺。不得把关闭证书验证、修改厂商签名包、假登录或全局替换网关作为接入方案。

## 原版桌面预登录验收

用户授权开始实机验证后，已重新告知官方联网和设备/路径/网关 URL 日志风险。Mac ARM 官方 0.34.5 原包签名再次核验后启动，应用显示真实登录页；点击登录后 Safari 打开官方 Accio 登录流程，尚需用户本人完成认证。没有代填密码、验证码或伪造登录状态。

启动前发现并修复一个实际缺陷：原型把带 `/api` 的地址作为 `GATEWAY_BASE_URL`，而官方桌面的目录与主模型工厂会自行追加 `/api`，会产生双重路径。现改为根路径，并使用原包 `xVr`/`DVr` 函数补验装配路径。官方隔离协议测试现为 9 项，Accio Rust 专项为 15 项，均通过；实验 Core 实际二进制构建完成。

当前临时守卫只用于登录/目录交互：主模型推理暂停，模型列表为明显标注的合成验收条目；固定官方身份端点可转发，其他路径拒绝，不记录 token、请求体、设备字段或 query。预登录已观察到 featureFlag、heartbeat、domain/config、update/beta-mac.yml 等非模型路径被拒绝。它们的存在说明通用网关兼容性尚未完成，不能据此宣称正式 Core 已适配整个桌面流程。原包还可独立访问其他官方服务，因此本次不是全流量或操作系统沙箱验证。

临时配置、凭据与 Electron 数据通过三个仅在原位置不存在时创建的链接隔离，空白测试工作区不包含私人项目。交互守卫最多运行 20 分钟；登录完成后的实机结果、进程关闭及链接清理应在后续验收补记，当前不能宣称本轮实机已经完成或所有测试进程已经退出。

## 2026-10-19 原版交互续验结果

前一日限时守卫已退出。本次重新启动官方 0.34.5 隔离实例后，浏览器认证完成；实际观察到 `/api/oauth/token` 与 `/api/auth/userinfo` 的 HTTP 200，原版进入 Agent 页面。原生输入框模型菜单显示合成验收 Alpha/Beta，切换 Beta 后标签随之变化；发送无文件读取指令后请求到达守卫，界面显示暂停推理错误。这一阶段没有发送元衡推理请求，只证明原版登录、目录、选择和模型请求入口可达。
