# Agent Note: Accio 主模型复用元衡 Core 的独立路由

Status: proposed

## Problem

用户需要官方 Accio 的主模型及模型菜单使用元衡分组。MCP 工具调用和重建 Agent 均不能满足此目标。[早期调研](2026-10-18-accio-work-integration.md)只确认官方账号可用，尚未实现模型桥接。

## Proposal

复用元衡配置入口、分组凭据、Core 生命周期以及 Responses 到各厂商的转换能力；增加独立 accio-work 命名空间。Accio 格式在边缘转换，不能共享或覆盖 Codex 当前模型和配置。参考 TF49/AI-Helper v1.0.69 的入口调查，固定提交 f94be4058b43d6e00778d157bf63f487d173b8ee；按 MIT 保留任何实际借用代码的声明。未复制其实现时仅记录研究来源。

官方 Mac ARM v0.34.5 包的主进程与 worker 均读取 GATEWAY_BASE_URL；主模型地址由通用网关拼接，ADK_BASE_URL 并不能单独接管主对话。启动环境仅作用于 Accio 子进程，不修改官方包、系统环境或 TLS 校验。本地原型放行已核对的模型目录和 generateContent 两个模型端点，依据原版登录实测另放行四个固定官方身份 POST 端点，其余路径明确拒绝，不暗中回退官方推理。新增非推理端点须有实际证据，不使用全路径官方回退补齐。

本地入口使用独立随机访问能力令牌，模型请求只能选择该分组目录中的模型；auto 只映射该分组已配置的默认模型。官方 token、cookie、设备字段与签名字段不进入重建后的元衡请求。模型流逐段转换；异常、上游断流、参数不支持均明确失败；不换协议重放、不回退官方、不静默截断对话。取消通过销毁流取消上游。未经原版及跨系统验证的接入不宣称正式支持、不发布。

四个已核实的插件目录/连接状态端点由[只读查询提案](2026-10-21-accio-readonly-cloud-queries.md)部分取代原全拒绝决定；官方账号与元衡推理凭据分离、无通用云端回退、禁止未经核实的工具执行等边界不变。新增实现仍在本地实验阶段，不能据离线测试宣称云端业务流程已通过。

## Local prototype

代码使用独立的 `accio_work_runtime` 设备本地表，保存同一请求使用的完整不可变供应商快照。最初原型使用schema21；与伙伴正式21的图像技能迁移冲突后，由[兼容迁移](../../implemented/bug-fix/2026-10-26-accio-upstream-schema-compatibility.md)统一到22并保留两种历史数据。WebDAV/S3 同步不导出该表，导入保留本机表；用户主动完整 SQL 备份仍会包含本机凭据。配置、账号切换、断开、目录与预检均走元衡已有入口，但不扩展 AppType，不获得 MCP、Skills、提示词文件或 Codex 配置写入能力。Core 复用 Responses 转换链，供应商健康外键表不为无 provider 行的运行时快照落盘，熔断器和请求用量仍使用 accio-work 命名空间。

Accio 没有可配置的鉴权头，网关 URL 路径承载本地能力令牌；接入拒绝非 loopback peer、非本机 Host 及所有 Origin。受控启动与活进程身份验证由 Core 持有，磁盘 active 标记不能独立授权；GUI 退出不影响活进程，Core 重启不接管旧进程。每次启动轮换令牌，退出或启动失败按相同令牌条件撤销，配置更新不能重新激活已撤销租约。断开删除配置。官方日志已观察到网关能力 URL，不能声称该本地令牌不会进入日志或遥测；它不是元衡 API Key，但仍是需披露的敏感信息。

入口受两端实验开关控制：前端 `VITE_ENABLE_ACCIO_WORK=1`，Rust `accio-work-experimental`；默认构建不显示工具、不注册路由、不接受配置/启动。仅做 macOS 官方签名、Team ID、Bundle ID 和 0.34.5 版本的启动约束；Windows/Intel 未实机验收。安装入口复用官方网页下载与安装观察，并提示官方安装器的电脑名称/设备标识上报，不能宣称元衡已验证安装包全流程。

独立 Core 不是 GUI 的 Cargo 编译产物。侧车准备脚本在 debug 且显式设置前端实验开关时传递相同 Rust feature，避免 GUI 有入口、Core 无路由；release 准备阶段拒绝实验开关。真正的桌面验收还需让 GUI 本身显式使用该 Cargo feature。

当前本机验证包含官方包原函数的隔离协议检查、Rust 模型/鉴权/撤销/同步排除/UTF-8/断流/取消与三上游协议往返测试、前端回归，以及 Mac ARM 原版连接实际 Core 的模型、切换、工具和取消验证。元衡 GUI 已完成路径选择、分组配置、启动和原生模型切换后的真实回复。单元测试使用假凭据；真实调用的隐私和计费边界、最终数量及剩余缺口以[兼容性报告](../../../../docs/reviews/2026-10-18-accio-work-compatibility.md)为准。安装/更新、云端扩展与其他系统尚未完成，因此笔记保持 proposed，不能把本机主模型验证写成完整交付。

原版桌面预登录核对发现 SDK 与应用工厂的 base URL 契约不同：实际 `xVr`/`DVr` 工厂自行追加 `/api`，启动环境只能给网关根路径，不能沿用 SDK 的 `/api` base。`gateway_origin` 生成不含 `/api` 的能力令牌根路径；新增官方工厂回归和 Rust 启动 URL 回归，协议检查为 9 项、Accio 专项为 15 项。这个缺口说明 SDK 构造器测试不能代替真实桌面装配路径。

原版预登录验收先使用临时守卫：主模型推理一律拒绝、目录是明确标注的合成验收模型，仅有固定官方身份端点允许转发，以便用户亲自登录；它不是正式 Core 的端到端验收。界面已到 Safari 官方登录页，不能假造登录态继续测试。所有账号数据位于临时目录，原本不存在的三个应用数据入口以可恢复链接指向该目录，不改已有用户配置。守卫有 20 分钟退出上限；等待登录的交互窗口不代表测试已完成，最终必须关闭其进程并移除临时链接。

## Existing decisions

Core 的 `AppType` 同时驱动本地文件、MCP、Skills 和旧格式迁移，直接扩展会默认赋予尚未验证的本地配置能力。桥接先采用独立 `accio-work` 运行时命名空间与不可变请求配置快照，复用 Responses 适配器；供应商状态、熔断、统计必须使用独立命名空间，不能因为复用协议而写入 Codex 状态。正式桌面生命周期完成前不将其加入默认工具列表。转换边界按官方包实际蛇形字段与 JSON 字符串处理，不等同 Google Gemini 线协议。

- 早期 Accio 提案部分重叠：保留包身份和隐私证据；本提案替代“只做官方账号启动”的产品方向，未改变未验证不能宣称支持的约束。
- [Codex 独立配置恢复](../../implemented/bug-fix/2026-10-14-codex-surface-mode-repair.md)只复用独立命名空间经验，不写 Codex 文件。
- [现有选路](../../implemented/architecture/2026-10-17-client-route-selection.md)可由 Core 复用；新桥接不得重新实现出站选路。

## Alternatives considered

- 搬入完整 AI-Helper：已覆盖很多 Accio 路径，但绑定另一套配置，读取整个上游响应后才回包，并存在协议重试和官方回退；不能直接作为生产桥接。
- 新建 Accio 风格 Agent：模型可控，但需要维护全套任务、工具和权限，不满足保留官方 Accio 的目标。
- 独立代理进程：便于实验，但增加端口、清理和多账号状态问题；产品应复用 Core 生命周期。
- 扩展通用 AppType：便于复用供应商管理，但同时进入本地配置、MCP、Skills 和迁移枚举，不能因为需要模型转发就授予文件投影能力。原型采用独立快照，复用协议适配而不复用这些应用写入入口。
- 通用官方透传：更容易保留全部云端功能，但未知端点可能包含推理或敏感数据发送，无法兑现不回退官方模型。原型拒绝未知端点，代价是部分官方工作流仍不可用，须用实机证据逐项补齐。
- Accio 边缘转换复用 Core：需要验证格式与请求分类，但避免重复维护厂商协议；选择此方向。

## Acceptance criteria

先用官方包真实函数及纯本地服务验证入口、目录、文本和工具往返。覆盖拒绝外部 Origin/错误能力令牌、跨组模型、压缩炸弹、未知内容/属性、工具结果 ID、UTF-8 分片、异常终止和取消；验证断开元衡后入口立即不可用。官方实机测试另记录包哈希、版本、实际路径、模型请求目的地和资源清理结果。所有测试使用假凭据或经用户明确授权的测试账号，无私有工作区。测试结果和遗留进程为零作为结束条件。

## Risks

通用网关替换会涉及官方登录、插件和云同步。环境变量属于版本相关实现，不是稳定公开接口；新版本必须重新验证。Accio 自身可能发送包含本机目录名的上下文与遥测，必须在联网实机测试前告知用户。Windows/Intel 未有实机结果，不能由本机通过推断全平台可用。

## Native verification: 2026-10-19

原版通过临时守卫完成 OAuth 及 userinfo，并在输入框显示、切换合成 Alpha/Beta 模型，证明真实桌面目录装配和原生菜单可接受该目录。正式 Core 仍缺少身份路径，不可把守卫结果当成产品通过。基于实测添加仅 `oauth/token`、`auth/userinfo`、`auth/refresh_token`、`auth/safe/refresh_token` 的 POST 转发，固定 HTTPS 主机 phoenix-gw.alibaba.com，拒绝 query、重定向、重试和未知路径；请求/响应均有大小与时限约束。官方 token 仅用于这些固定官方身份端点，元衡 key 不注入，原始 header/body 和 URL 中能力令牌不记日志。其他功能路径继续拒绝，完整 Agent 工作流仍待验证。

随后使用实际实验 Core 二进制、独立数据库、随机端口和现有元衡分组快照完成原版 Mac 对话：gpt-5.6-luna 返回 YHOK，同一对话原生菜单切换 gpt-6-luna 后返回 YHSWITCH；文件读取工具在一次调用后把合成文件内容 YHTOOLCHECKOK 通过后续模型调用返回，界面状态 finished。停止生成后 Core 活跃连接回到 0。该验证直接连接实际 Core，不是之前的合成目录守卫；但测试驱动直接构造隔离配置并启动应用，尚未覆盖元衡 GUI 的完整一键安装/配置/启动流程，也不能推广到 Windows/Intel。

实测修复两个此前模拟未覆盖的协议点：官方 Tool protobuf 为扁平声明，必须保留 name/parametersJson；原版消费者跳过 turnComplete=false 的 functionCall，因此先校验/暂存已完成工具条目，直到 response.completed 再一次性输出完整工具调用。模型文本仍逐段输出，未完成上游绝不能执行部分工具参数。真实元衡流中的 codex.rate_limits、codex.response.metadata、response.metadata、responsesapi.websocket_timing 仅作为已识别元数据忽略，未知内容事件继续失败。原包提取测试覆盖真实工具声明和消费者条件，不能仅测试底层 SDK 能反序列化。

原型仍保持 proposed/默认关闭：云端插件、媒体、团队、子 Agent 选路及官方升级未验收；当前白名单会拒绝这些路径。官方组件确实可能自动发起标题等辅助模型请求，短提示主请求也约 3.7 万输入 tokens；不能承诺一次点击只计一次调用。该测试中的本地请求日志早期有 HTTP 200/零 token 的中断记录，它们是用量未知，不是模型成功或零费用凭证。最终结果见兼容性报告。

## GUI 验收约束

隔离测试构建须使用独立 Bundle ID、数据目录、Core 端口，并清空该构建的 updater endpoints，避免正式更新覆盖实验入口。当前 Core 的系统服务标签并不随 Bundle ID 改变，验收通过预启动独立 Core 避免替换用户既有 LaunchAgent；这不覆盖首次安装后台服务。

元衡账号必须是正常登录的独立测试会话；不能复制原会话 selector，使测试退出时删除正式客户端的 Keychain 项。隔离 GUI 正常登录后完成主模型流程。新增合成账号测试覆盖真正的配置函数与账号持久化入口：混合协议分组目录、未启动不激活、换模型保留租约、换账号撤销旧配置和 Codex 文件不变；它不是 GUI 通过的替代证据。

Accio 工具卡使用“启动/应用并启动”，不显示其他桌面工具的“刷新显示/应用并刷新”。只有支持受控重启的桌面工具才传递 restart；Accio 已运行时仍要求用户先保存并退出。成功启动后清除该工具的待重启标记，失败时保留；不自动终止用户的 Accio 会话。

Tauri dialog 2.6.0 的初始化脚本将 `window.confirm` 替换为异步 IPC。Accio 下载和启动入口必须等待其结果；把返回值直接当布尔量会把未确认的 Promise 当成同意。下载入口复用现有 AbortController 管理确认等待，卸载页面或停止观察后即使收到同意也不打开外部地址。异步允许、取消、失败及卸载后迟到结果均有回归，普通浏览器的同步确认仍可用。实机发现这一问题的依据是确认框仍打开时，原版 Accio 子进程已启动；不能只用同步 mock 验证该交互。

修复后实机验证了未确认不启动、取消不启动、明确同意后仅启动一个官方子进程，退出后目录返回 401，重开轮换能力令牌。本机官方样本发生了 0.34.5 → 0.35.2 自动更新，元衡受控入口正确拒绝未知版本。自动更新重新启动后的环境继承仍是发布缺口，不能由一次受控启动推断后续所有进程均沿用元衡网关；版本检查维持严格，现阶段不承诺无人值守升级兼容。

## 发布前诊断缺口

生命周期修复由[Core 子进程所有权决策](../../implemented/bug-fix/2026-10-19-accio-core-process-ownership.md)接管；以下保留原缺陷复现依据，最终落地结果以该篇与兼容性报告为准。

修复前的独立 Core 残留状态实验表明：GUI/Accio 均不存在时，active 配置仍接受原能力令牌，Core 崩溃后同端口重启也接受。问题归属于 GUI 内的子进程等待任务，不能处理 GUI 先退出的顺序。现由 Core 持有 Child、逐次校验和周期清理处理，复验旧地址返回 401；正常退出已通过的结论仍不得扩展成所有官方更新可自动恢复。

官方 0.34.5 的本地日志在未知连接器端点返回 501 时，每分钟持续约一万次 authorization/status 请求；这些不是计费模型请求，但会造成日志和资源开销。未知端点的拒绝策略仍需最小兼容/退避设计与空闲负载验收，不能为了停止重试而开放通配转发或伪造认证成功。

0.35.2 的 9 项离线目录/环境/缓存/工具消费条件检查通过，测试源码锁定官方 worker 哈希且不发送外部请求；它不包含完整新协议序列化、GUI 对话或更新重启。上次 20:22 的官方网关恢复在旧版被非受控重开后已经发生，时间早于新版下载，不作为自动更新丢失环境的因果证据。具体量化结果、测试限制和复现入口归属兼容性报告。

## 连接器失败回路修复

官方 0.34.5 的 manager 在查询失败后发布 `connector.authorization.snapshot`，renderer 收到不含快照的事件后清除 retryAt 并重新查询，因此 Retry-After 头本身无法限制回路。仅对实测的 `channel/query` 和 `channel/authorization/status` 在本机及能力验证后延迟 5 秒返回真实的 501 不支持；等待不占模型/身份请求槽，不持有身份正文，没有后台自旋，取消即释放计时器。每条被官方 inFlight 合并的串行反馈链最多约 12 次/分钟，不能据此宣称所有连接器总量均受此限值限制。

本机 POST 无 query 的同两条查询在 capability 已失效时也延迟 5 秒后返回真实 401，防止 Core 重启把旧循环变成另一种即时失败。其他失败、模型、登录和未知路径不进入该兼容等待。模型/身份读取有界正文后再次检查当前 Core 的活进程与能力令牌，读取过程中撤销的请求不能开始新的上游调用；已经发出的流不被此检查追溯取消。

真实备选包括返回成功的空账号列表，但官方 `applyRemoteAuthorizations(clearMissing:true)` 会据此删除已连接账号缓存并发出 disconnected，故不能用于“不支持”语义。通配透传会扩大数据与推理范围，也不采用。保持立即 501 则不能阻止已复现的事件反馈回路。受限延迟拒绝保留错误提示和已有授权缓存，代价是连接器状态失败需要等 5 秒；其本身仍未支持云端连接器。提取原版 manager/renderer 的离线回归用于证明取舍，短时实际空闲运行另外验收频率、日志和资源。

## 新版原生兼容性探测

在正式启动器放行新版本之前，需验证官方 0.35.2 的实际工具和对话，而非只测目录。复用现有 ProxyServer 和 Runtime 的测试编译入口，要求显式提供本地权限受限 fixture；默认 ignore，固定官方签名、身份与 0.35.2 版本，限定时长和请求数量，结束清理进程。该入口仅 `cfg(test)`，不进入产品二进制，也不改生产版本门禁。它只验证新版协议/原版 UI 与当前转换链，不冒充元衡 GUI 已支持新版。

最新离线检查 15 项包含真实 protobuf/transport/SSE/取消。测试编译入口实测 0.35.2 恢复会话、目录和原生菜单；luna 读写命令完成但最终回复失败，sol 的最小回复及 read/bash 结果回传成功。第一次120秒窗口未取得完成模型记录不算通过；测试入口现默认300秒、可显式指定30–900秒，完成模型记录达到10后停止（不是严格请求/计费上限）。生产门禁仍为0.34.5，失败记录及测试编译与GUI范围分别说明，不能直接称全功能兼容。

备选是先放宽正式版本再试，风险在于验收未完成即改变用户可启动范围；或只做离线序列化测试，其无法验证原生工具执行与 UI 消费。选择测试编译探测保留版本限制，代价是新版通过仍需后续 GUI 与更新继承验收。真实元衡 Key 仅来自已授权的本机分组测试快照，不写日志或提交；新设备 VM 不导入宿主登录，必须由用户亲自登录后测试。

2026-10-20 干净 VM 已完成用户真实登录后的元衡GUI配置、Core首装和关机重开；0.35.2探针需从GUI会话域启动才能正常读取原加密凭据，SSH直接启动的safeStorage不可用不是手机号协议失败的证据。正式Core已有GUI LaunchAgent，未据此修改产品认证实现。手机号userinfo200、7模型原生目录和sol最小回复通过，切换后的完整回复和文件任务仍欠验证；后者被宿主锁屏阻止。版本预检目前晚于配置副作用、成功文案不能反映已安装版本支持，是待修产品问题。结果和清理见[干净设备验收](../../../../docs/reviews/2026-10-19-accio-clean-macos-vm.md)，不放宽0.34.5门禁。
