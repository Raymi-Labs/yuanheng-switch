# Agent Note: TRAE 内部登录会话与模型保存服务桥接

Status: proposed

## Problem

缓存两轮实测均被启动刷新覆盖，扩展命令探测也未发现主模型保存命令。用户要求继续完成与其他Agent一致的配置体验，需要验证实际模型保存服务，不把目录缓存或工作区LLM集成误当主模型配置。

## Proposal

在TRAE扩展进程内调用官方已注册的`icube.cloudide.getByteCloudToken`取得本次请求授权，只允许发往当前官方安装包bootConfig固定的国内版HTTPS服务。先只读providers查询验证适用性；不读取日志/解密数据库、不向元衡导出登录授权，不记录响应原文。只使用正常官方登录，授权缺失或错误直接停止。

若只读验证通过，再在原先已授权的官方模型保存范围内验证独立测试条目的新增、目录读回与重开。最终产品必须有显式用户动作、账号/模型范围、固定origin、无重定向、超时、取消、原配置保护和可卸载扩展；用户选择仍在既有工作台和工具卡中，不新增孤立入口。元衡Key只按用户选择传到同一官方服务，持久化与协议分别验证。

## Verification and current blocker

固定国内版3.4.9、build 2.3.97430，在扩展进程中使用官方会话命令完成以下验证；授权仅在内存使用，报告不包含token、真实Key、账号或设备标识。

| 检查 | 结果 | 能证明什么 |
| --- | --- | --- |
| 官方providers读取 | HTTP 200、code 0、20个provider | 登录会话及固定官方域名可用 |
| 直接保存独立合成模型 | HTTP 200、code 0；重开后原生菜单可见 | 记录可持久化，不代表密钥可用 |
| 原生选择合成模型并发送一次请求 | 错误2001，`invalid message: invalid ak`；本机合成服务收到0个请求 | 此保存路径没有完成可用凭据处理，不能上线 |
| `getWebSocketRpcClient`源码核对 | 扩展入口存在，MainThread的`$makeRPCClient`直接抛出not implemented | 当前版本不能借该入口调用原生保存服务；不是实际RPC成功证据 |
| 清理及重开 | 精确删除合成条目返回HTTP 200、code 0；两份缓存原有自定义行数恢复30/21、测试行数均0；原生菜单只余原有3个条目 | 测试模型清理已确认；恢复原Astra Responses选择 |

本轮未证明密钥编码算法，不能把错误推断写成已经确认的加密格式。没有提取或复用原有模型密文、解密官方数据库、修改签名应用或引入调试注入。原生编辑表单只查看了合成条目，未保存；真实Key未再次提交，没有付费推理。

四个自建探测扩展的官方CLI卸载均受`isProtectedExtension`异常阻止；退出应用后将精确匹配的四个目录移出扩展安装目录，并从索引仅移除对应四项。其他扩展索引完全保留；重开后无探测扩展残留。隔离目录可恢复，合成模型没有真实凭据，无需恢复。合成服务已关闭，19479无监听，临时探测/服务进程0；测试会话历史保留供排错。

下一条未验证路线是通过原生表单自动填写，让官方自己处理密钥；它需要另行验证跨平台辅助功能权限、焦点与窗口变化、取消及失败恢复。当前没有此产品实现，不能将一次人工界面操作当作可发布的自动化。提案保持proposed，不新增空壳工具卡、不改产品成功状态。

## Alternatives considered

- 原生界面自动填写：可以让TRAE自己处理登录，但系统辅助功能权限和界面版本变化增加维护成本；若此内部会话路线不成立再测试。
- 从官方日志提取token：社区已有例子，但会扩大敏感读取和导出范围，不采用。
- 当前会话授权只在TRAE扩展内部使用：减少跨进程凭据暴露，代价是仍需核验非公开接口的版本、字段和失败恢复；先做只读实验。

## Acceptance criteria

固定官方域名和授权来源可确认；只读查询明确成功后才作写入；保存后目录、原生UI、重开和实际请求一致；未知版本/账号变化/缺授权拒绝。无新目的地泄漏、不关闭TLS或代理安全规则、不自动重发模型请求。结束卸载探测扩展、临时进程为零。未通过前不改变产品的已接通状态。

## Risks

登录授权可代表官方账号，本轮已告知用户使用范围；仅内存持有、请求固定官方origin、禁止重定向、报告只保留状态码/计数。接口并非公开稳定契约，不能因一次请求通过承诺全系统或长期兼容。
