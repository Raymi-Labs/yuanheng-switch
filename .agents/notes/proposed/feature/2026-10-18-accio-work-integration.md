# Agent Note: Accio Work 先区分官方启动与元衡模型接入

Status: proposed

## Problem

用户希望在元衡中使用 Accio Work。若仅添加下载启动入口却显示已接入元衡，用户会误以为使用元衡模型和计费。官方 v0.34.5 的本地协议测试显示，主模型目录和推理依赖 Accio 网关协议，不能直接替换成 OpenAI Base URL/API Key。

## Proposal

本轮先交付[兼容性证据与执行方案](../../../../docs/reviews/2026-10-18-accio-work-compatibility.md)及本地测试脚本，不修改产品运行流程。若执行基础接入，复用工具管理/工作台生命周期，明确标为官方账号工具，禁用元衡模型配置。取得官方 BYOK 接口并完成端到端验证后再启用元衡模型功能。完整协议转换留作独立研究，不承诺其可行。

安装前说明已发现的设备标识和电脑名称上报；保持官方包签名，系统授权由用户操作。元衡不读取或迁移官方登录 token，不把元衡密钥交给不支持的接口。

## Existing decisions

检索现有安装、下载、工作台笔记：与[工作台直接安装](../../implemented/bug-fix/2026-10-17-workspace-direct-install.md)的入口部分重叠，复用生命周期；与[官方下载选择](../../implemented/architecture/2026-10-17-direct-download-selection.md)只有下载基础设施相关，其元衡 R2/GitHub 候选不可用于第三方 Accio 包。其余模型路由决定不适用于 Accio 的专用协议，不替代现有笔记。

## Alternatives considered

- 直接复制 WorkBuddy 一键模型配置：成本低，但两者协议和配置入口不同，模型目录会请求错误路径，不能交付。
- 只放下载链接但仍显示元衡配置按钮：入口简单，但误导模型来源和计费；必须先建立工具能力分离。
- 改全局网关并模拟官方协议：可能提供更深接入，但会牵涉登录、签名和非模型服务，端到端尚未证实，维护面过大。
- 官方账号启动适配，模型适配以官方接口为准入条件：能清楚交付已知能力，但暂不能满足直接使用元衡模型的需求。

## Acceptance criteria

本轮包验证、6 项本机协议级测试、原版 Mac ARM 登录、官方模型菜单切换和一次最小单轮推理通过；测试应用及监听进程为零，隔离数据链接和临时测试目录已清理。推理日志确认请求上下文含本机用户目录下的多个绝对路径；未完成文件正文发送情况审计。同一运行期间还观察到 Accio 设计编辑器 MCP 请求，触发来源未确认，不能把模型返回的工具调用数为零理解成应用没有其他后台请求。实施时需在两个元衡入口覆盖下载失败、签名不匹配、取消、安装观察超时、多安装副本、手动路径和启动失败，Mac/Windows 实机通过后方可宣称支持。没有官方 BYOK 验收前，不显示元衡模型/分组配置成功。

## Risks

协议测试范围是 v0.34.5 官方 Mac ARM 包的抽取函数和模拟接口；真实运行验证只覆盖登录、模型选择及单轮无工具回复，未覆盖多轮、流式、取消或文件/工具边界。运行日志暴露本机工作区绝对路径已告知用户，文件正文是否随上下文发送尚未确认。官方包存在设备信息上报，应向用户说明。Windows/Intel 包签名尚未核验。私有网关环境变量不是稳定公开的第三方接口。没有官方自定义模型接口时，可执行范围只有官方账号启动整合，不能把它等同用户原本想要的元衡模型接入。
