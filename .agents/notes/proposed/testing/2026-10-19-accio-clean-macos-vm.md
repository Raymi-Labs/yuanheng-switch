# Agent Note: Accio 新设备安装在独立 macOS 虚拟机验收

Status: proposed

## Problem

已完成的隔离目录测试验证主模型和 Core 进程行为，但不能证明新用户从官方下载、执行 PKG、安装服务、空钥匙串登录到首次调用都可用。官方 PKG 写 /Applications、查询控制台用户和机器标识并自动启动应用；元衡同一用户的 Core 服务标签与钥匙串服务名固定。仅更改数据目录不能避免宿主状态参与结果。

## Proposal

在用户已授权的 Apple Silicon Mac 上创建独立 ARM macOS 虚拟机，用 Apple 恢复镜像初始化空系统盘。虚拟机用中性本地测试账号/电脑名，不登录 Apple ID，不复制宿主账户/钥匙串/浏览器/Accio 登录态。关闭剪贴板、音频、USB 共享，不挂载用户主目录；仅必要时挂载专用只读测试安装材料。

2026-10-21用户明确要求支持复制粘贴后，人工入口的剪贴板边界由[授权共享决定](../../implemented/testing/2026-10-21-qa-vm-clipboard-opt-in.md)部分取代；run/run-test/provision与空白基线继续保持隔离，不改写此前验收条件。

虚拟机文件和管理工具位于本机专用验收目录，独立 TART_HOME。虚拟化工具从固定版本官方发布下载，校验 SHA-256 和 macOS 签名；不安装 Homebrew 或宿主后台服务。运行禁用继承的 tracing 配置，日志权限受限；虚拟机在交互测试结束后关机，不留下持续占用 CPU 的进程。

元衡测试包开启前后端 Accio 开关，使用正常应用 ID、Core 安装路径和服务标签，仅在虚拟机内启动。测试包关闭 updater 来源，避免正式包替换实验入口。它是本地实验构建，不能当成正式签名安装包发布验收。Accio 必须通过实际官方 PKG 安装，不能以解包复制 App 代替。

## Existing decisions

[主模型桥接](../feature/2026-10-18-accio-primary-model-bridge.md)部分重叠，保留本机主模型验证结果；本篇专门覆盖此前未验证的干净设备安装边界。[Core 所有权](../../implemented/bug-fix/2026-10-19-accio-core-process-ownership.md)继续负责授权生命周期，不因 VM 测试放宽版本或模拟生产登录。检索其他安装笔记主要涉及 Windows Claude 系统组件，与本篇不重合。

## Alternatives considered

- 临时目录/独立 Bundle ID：准备快，已验证协议和 GUI；但系统安装路径、机器名称、控制台用户、服务标签和 Keychain 不隔离。
- 宿主新增本地用户：可分隔部分登录与配置，但共享 /Applications、操作系统安装状态与机器标识，也需要切换登录会话，仍不足以测试全新系统。
- macOS 虚拟机：需要下载恢复镜像和磁盘空间，但独立系统盘可保存干净基线，安装脚本、系统服务和测试账号不使用宿主身份。选用此方案，真实账号登录仍由用户在 VM 完成。

## Acceptance criteria

确认 VM 内无元衡/Accio 配置和登录态，保存关机基线；实际装包并核对身份；元衡在未预启动 Core 的条件下创建服务，VM 重启后服务恢复。下载确认取消不打开网站，同意后到官方来源；官方安装器自动打开 Accio 时元衡引导明确，不能假称已接入。用户正常登录后，选择分组、启动、最小合成任务与原生模型切换需实际验证。记录官网安装版本与应用内更新版本，未知版本继续拒绝。结束验证 VM 停止、测试端口与进程为零，宿主原有服务/配置不变。

## Risks

VM 网络仍通过宿主出口，不能宣称网络匿名；官方安装统计可包含虚拟机名称和设备标识哈希，须预先告知用户。首次元衡/Accio 登录、验证码等需要用户本人完成，不复制旧会话来伪造首次登录。新 VM 初始化与实验测试包通过不等于已完成正式发布包和所有系统验收。

## Bounded continuation

上轮300秒窗口同时消耗于图形控制和任务执行，不能取得完整切换证据。本轮继续复用仅测试构建的原生探针：时长默认300秒，fixture可显式取30–900秒，启动前验证；完成模型记录达到10时停止并保留stop/进程组清理。该阈值不是严格计费请求上限，标题和在途请求均可能额外存在。新增权限受限原子progress文件只包含经过秒数和已完成模型/status/token，不包含prompt、登录或capability，最多两秒更新一次。

备选是反复使用300秒窗口，但会反复消耗登录/UI准备时间且难以验证同会话切换；无限延长则违背有界测试和零遗留要求。选择最多900秒且拆分模型切换与文件工具两轮，代价是每轮仍需要独立清理与人工最终回执核对。菜单选中、完整回执、实际模型记录必须同时成立，单独HTTP200或零记录不作为业务结论。此调整不修改产品0.34.5门禁。

## Manual UI fallback

用户手动打开VM后，CUA仍出现能截图但坐标点击报`noWindowsAvailable`的现象。重复切换全屏/重开已无足够收益，不能用API直发或手工生成输出文件冒充原生验收。为继续相同验收，提供本机专用手动入口：由用户在实际Accio界面选模型、发送固定合成提示，探针仅在原测试边界内记录脱敏已完成请求；终端Enter/Ctrl-C或有界期限结束清理并正常关闭VM。入口不安装宿主服务、不把私密profile复制到宿主，不新建元衡token，不调整产品版本限制。

该入口只有用户明确运行时才启动，不是计划任务；输出须标明真实调用可能计费、后台标题也可能产生额外请求、报告不自行判定业务通过。最终仅支持`--existing-vm`，用户先使用原有入口打开固定QA虚拟机，手动测试入口不负责开机。拒绝既有Accio与测试重入，使用唯一报告目录，保留官方登录，删除本轮fixture并卸载精确临时服务标签。若本轮运行未建立，清理不得关掉用户原会话；成功建立后，终端明确告知结束将关闭专用测试VM。代码/合成测试通过不能写成人工UI流程已验收。

曾尝试由包装入口代为启动VM，但实际多次返回通用VZErrorDomain1，而原直接启动方式成功。去掉detached后仍出现，不能把根因确定为进程组或PTY；不继续扩大诊断，撤回自动开机路径。最终复用已有QA VM的无消息真实冒烟通过：探针running、完成模型记录0，Enter结束后fixture删除、job移除、进程0、listenerfalse、正常关机且无fallback；宿主原配置不变。该冒烟不包含模型切换、工具或实际Ctrl-C验收，信号路径仅经合成检查。

停止后另取最终summary的脱敏模型投影，保存`final-models.json`，避免第三条刚完成便结束时漏读最后记录。最终证据缺失应单独标记且继续关机，旧progress不能替代；投影和缺失分支通过合成检查，完整人工模型切换仍待执行。

2026-10-21用户双击入口立即报manual_test_failed后关机，宿主没有progress，guest的ready/progress/summary都不存在且stdout/stderr为空。增加脱敏异常类别/阶段/脚本行号后成功复现：status与stop都在File.read共享manual-switch-control.json处抛Errno::ENOENT，而宿主控制文件存在；读取跨机更新文件的可见性不可靠，未将其归因于账号、版本门禁或语言设置。

修复复用现有SSH stdin：固定schema的runId/action与本地Ruby helper一起传递，经大小/动作/ID/提权一致性校验并编码，guest读取后删除临时环境项；不再读取共享的可变控制文件，宿主控制文件只用于审计与锁归属。共享目录继续只读提供固定二进制材料。入口等待ready且job仍running后才显示三步提示，最多90秒，取消/提前退出进入原清理流程。未采用共享文件轮询重试，因它仍依赖跨机可见性；未关闭异常清理或放宽正式版本门禁。

验证包含未知动作/错误ID/提权不符/超大输入/分隔符注入拒绝、直接stdin传递、原始错误不输出、就绪/提前结束/超时/取消及旧清理合成回归。原失败运行与复现运行的fixture/job已按owner精确删除后释放死锁。真实无消息运行在中文locale环境下达到running并连续状态检查32秒，Enter结束后最终summary可用、模型记录0、fixture/job删除、进程与listener归零、正常关机、无fallback/errors且锁释放。该结果证明手动入口故障修复，不替代原生三次模型回复验收。

## Current evidence

2026-10-21续验启动前发现guest已安装官方签名有效的0.35.3，原0.35.2测试入口必须拒绝它。先核对已安装包中的网关环境、模型目录、SDK请求/流解析等实际代码，再将固定版本与哈希加入离线检查和仅测试编译入口；正式0.34.5门禁保持不变。不改写已安装官方应用，也不为了沿用旧测试而降级。选择复用原受控生命周期和脱敏报告，成本是每个新版本都需要复核；直接放宽成任意0.35.x会绕过协议证据，故不采用。用户已确认人工复制粘贴可用，但CUA坐标操作仍失败，原生切换必须有实际UI完整回复和对应模型记录，不能用直发API替代。

上次manual-switch运行的临时fixture和服务已精确清理，确认进程/监听为0后移除宿主死锁与控制文件。旧最终模型证据仍不可用，保留其报告，不补造通过结论。
