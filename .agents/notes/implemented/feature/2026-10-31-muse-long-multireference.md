# Agent Note: Muse长片与多参考图文档适配

Status: implemented

v0.1.120发布准备：已有另一会话的60秒四图样本成功生成并下载，但第2–4图效果未通过；页面在选择多图时和发布公告明确标为实验，180秒仍未实测。不改变用户已授权的输入范围，也不宣传已完成全量实测。

## Problem

用户提供20261028 Muse上游文档，要求本会话调整客户端，另一个会话执行实际生成。现有30秒/单图、10分钟轮询和64MB内存成品读取不覆盖文档180秒、4张参考图、95–165MB长片。

## Decision

仅Muse扩展4–180整数秒、默认4秒、720p两方向、4000 Unicode码点提示词。兼容旧reference，新增images仅Muse接受；两字段互斥，单图input_reference、多图images，PNG/JPEG/WebP单张10MiB/总24MiB且逐张真实解码。界面可添加/删除/调整顺序，第一张首帧，其余人物/场景/画风，最后不是尾帧；切离Muse多图明确提醒。

Muse查询每15秒最多120次（约30分钟，加上查询耗时）。用户随后要求三分钟视频预留30分钟等待，因此Muse提交期限改为1800秒，其他视频仍600秒、查询20秒；失败暂停保留原任务不重发。请求级timeout覆盖共享HTTP客户端600秒默认总期限，不扩大其他模型等待。超过30秒说明分段拼接，不能称为连续长镜头；不引用上游价格作本站售价。

视频成品流式写入私有临时文件，900秒下载、256MiB上限，完整且MP4头正确才原子发布。保存从文件复制而非全读内存，已有大于64MiB作品不经base64预览，提示保存后播放。无HEAD/Range/付费重发，失败临时文件释放。保留普通图片64MiB边界。

## Alternatives considered

- 仅扩时长最简单，但必然让大作品超过原64MB限制；同时修下载链。
- 把所有成品全量base64传前端易于预览，但长片倍增内存与IPC负担；大作品使用流式下载和本机保存。
- 每个Agent/模型统一多图字段减少分支，但会改变其他厂商已验证协议；仅Muse启用images和WebP。

## Adversarial review

reference/images互斥由原生验证，不靠UI；多图只扩Muse，单图和其他型号保持原字段。先检查单张编码上限，逐张有界解码后累计总字节，序列号防旧文件读取覆盖新草稿。切离Muse清理多余图片并提示；长片时长必须为目录允许的整数，默认值仍4。

大视频不经过内存body/base64导出：先写私有临时文件，验证状态码、大小、MP4头、流完成并核验会话后发布；保存以文件复制到目标目录临时文件，成功后替换目标，失败保留原目标。内嵌预览上限仍64MiB，超限明确引导保存，允许重试下载但不重放生成。作品文件/目录隔离和互斥保持。
