# Agent Note: 顶部一行显示可用更新

Status: implemented

## Problem

工作台更新入口是工具栏末尾的无文字绿色小图标，不够醒目；忽略版本后入口也会消失。用户要求最上面一行显示带红点的更新按钮，仅在没有新版本时隐藏。

## Existing capabilities and impact

[UpdateProvider](../../../../src/contexts/UpdateContext.tsx) 已统一检查状态、忽略/延后偏好和安装互斥；[UpdateBadge](../../../../src/components/UpdateBadge.tsx) 仅展示已有结果；[App](../../../../src/App.tsx) 的顶栏位于登录与工作台分支之外，可复用并避免每个页面各自挂载。Mac 顶栏已有拖动预留，Windows 和普通 Linux 无预留，Linux 可选自绘窗口按钮。

活跃笔记检索：与[免登录更新](../bug-fix/2026-10-10-update-without-login.md)部分重叠，保留其手动恢复入口并互链；钥匙串、账号密码和签名发布笔记仅提供相邻边界，不改变其决定；DSH 安装和工具安装笔记无关。

## Decision

将 UpdateBadge 移至全局窗口顶行，显示更新文字、版本号与静态红点。可用版本来自现有 hasUpdate/updateInfo；忽略和稍后提醒只影响自动弹窗，不隐藏被动入口。主动点击清除该次忽略/延后并打开既有 UpdatePrompt；无更新时不显示，也不为更新保留额外空白。下载/安装时展示忙碌状态，禁止重复操作。

顶栏沿用平台拖动规则，按钮区域禁止拖动，和窗口控制按钮留出间距；登录、加载、两步验证及工作台页面共享该入口。登录页在未发现新版时保留手动检查，已有新版时只由顶行提供升级动作，避免重复按钮；检查/下载失败的官方备用下载入口和关于页手动检查保留，便于自动检查关闭或网络失败时恢复。复用原签名下载与重启流程，不新增更新请求或修改检查频率。

## Alternatives considered

- 只放大工作台工具栏图标：改动最少，但仍混在其他工具按钮中，且登录页不共享；使用全局顶行。
- 无更新也一直显示强提示按钮：用户总能发现入口，但违背仅有更新时醒目的要求；保留已有手动检查作为独立恢复出口。
- 忽略版本后继续隐藏：尊重旧图标行为，但用户要求有更新就能看到；保留自动弹窗的忽略偏好，只改变被动入口。

## Verification

899 项前端测试通过，包括真实 UpdateProvider 下的有/无更新、忽略与稍后提醒、检查失败保留已知版本、下载/安装禁用、失败后重新打开，以及 App 登录和工作台分支中的顶栏入口。登录页只显示一个可用更新按钮，原手动检查和错误备用出口仍可用。类型、格式、版本一致性、renderer 构建及 Rust 格式检查通过；renderer 仅有原有体积提醒。

浏览器使用真实 App 壳和隔离模拟 IPC，验收深浅色、1280×720 与 900×600、Mac/Windows 顶栏、Linux 自绘窗口按钮、无更新隐藏且不额外占位、忽略后重新打开、登录加载中、二次验证和下载失败。模拟未调用实际安装或恢复凭据。Windows/Linux 为浏览器布局验证，非真机安装；正式包以 v0.1.73 发布流水线、签名公证和公开更新源验收。

v0.1.72 的发布前 Linux CI 发现新增测试对空顶部栏执行样式断言；该版本未生成或发布安装包。修正为比较有更新前后原平台高度（允许无顶部栏），并以 Linux UA 重跑，随后使用 v0.1.73 发布，不改写已推送的旧标签。

## Consequences

有更新时顶栏需要容纳文字并增加到 36px；无更新恢复原平台高度。用户忽略版本后仍看到被动提醒，但不会额外自动弹窗。后台检查频率与开关沿用 UpdateProvider；按钮只展示已检查到的新版，不冒充网络失败为“已是最新”。登录页不再重复显示可用更新动作，未发现版本或失败时仍有主动恢复出口。安装依旧会重启桌面端，不改变账号、工具配置或更新签名策略。
