# Agent Note: 工具按厂商与分组级联选择模型

Status: implemented

## Problem

工作台按厂商、模型、分组三个独立控件选择，工具管理先选模型再保留原分组。DeepSeek 企业分组切到 Grok 时，浏览中的新厂商与原模型/分组分属不同状态，用户难以一次选择有效组合。网络读取失败是独立问题，调整选择器不能代替连通性或实时权限检查。

## Decision

两处工具入口共享两个下拉框：厂商，以及分组 → 模型的级联弹层。复用 modelVendors、账号 modelGroups/groups、Popover/cmdk、本地收藏与既有预检/配置命令；不新增后端目录或权限来源。厂商和分组仅改变浏览状态，只有点击模型叶子才产生完整的 {model, group} 选择。只展示当前账号目录中同时存在的厂商模型与分组关系，不沿用其他厂商分组、不默认选中模型、不在缺少映射时猜默认组。

工作台沿用立即预检并应用；工具管理保留草稿后配置/启动，Codex 继续即时应用。明确选择组合无需再次询问是否更换分组。失败保留原配置，推理等级依新模型归一化；搜索、收藏、取消和刷新均不提交。后台刷新保留弹层，账号/工具切换重置浏览状态。目录外旧配置仍可看见，但不能变成新候选。

## Existing notes audit

- [模型层级](../../implemented/feature/2026-10-02-model-picker-groups.md)部分重叠：独立 ModelPicker 保留，工具配置入口由本篇替代其先模型后分组顺序。
- [本地收藏](../../implemented/feature/2026-10-04-model-picker-favorites.md)部分重叠：存储、权限及星标不提交规则保持，工具入口的两个独立选择器替换为级联。
- [工作台入口](../../implemented/simplification/2026-10-12-workspace-single-tool-controls.md)部分重叠：单工具操作区和保存时机继续适用。
- 账号线路和请求用量归属笔记不持有此选择交互决定，不作替换或归档。

## Alternatives considered

- 保留三框并在切模型后自动选组，改动较小，但隐含选择可能改变费用及渠道，且用户仍看见冲突组合；采用显式选择叶子。
- 三框改为厂商、分组、模型，可以过滤冲突，但用户明确要求两个下拉框；在第二个弹层展示两层目录。
- 只调整 DSH 能覆盖当前反馈，但其余工具共用同一选择路径；共享两处入口，避免模型/分组规则分叉。

## Verification

149 个文件、978 项前端测试通过，类型、renderer 构建、格式、版本一致性和笔记检查通过。新增级联组件 8 项测试、DSH 完整 App 两入口切换测试，以及组合成功/失败和账号变化中止预检测试。既有工具管理回归改为通过真实级联选项完成选择，继续验证草稿恢复、批量配置、快照和 Codex 即时保存。账号变化时取消旧预检继续写配置；两项旧测试改为等待模型数据就绪后再操作，避免在静态工具列表出现时提前切换。

真实 App 壳在隔离 Chrome 中以模拟 IPC 验证 DeepSeek 企业组 → xAI/Grok 标准组的完整切换，分组点击、收藏和 Esc 不提交，模型叶子把两值一同传入既有配置命令。模拟预检失败保留原组合且不写入；目录刷新失败保留弹层与已知候选。ArrowLeft/ArrowRight 展开收起、Enter 提交均通过。1440×1000 浅色、900×600 深色弹层截图已复核，窄窗口无水平溢出。工具管理选择仍先保留草稿，配置时使用同一组合。浏览器未连接真实账号、写本机工具配置或调用付费模型，不证明原生 WebView、真实上游权限或网络恢复。

## Consequences

完整组合选择减少跨厂商切换时的分组冲突，但目录同步不完整会减少可选组合，因此显示刷新提示并保留原配置。厂商识别继续是模型名启发式；客户端筛选不替代后端实时预检。浏览器模拟不证明真实付费推理或用户设备网络恢复。
