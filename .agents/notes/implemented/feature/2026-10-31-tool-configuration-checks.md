# Agent Note: 工具配置验收与就近诊断

Status: implemented

## Problem

配置成功仅证明写入，不能证明应用已读配置或模型已完成。工作台已有五步生效状态，但工具管理仅 Accio 展示；失败只显示 HTTP 数字，旧成功与当前路由故障可能同时显示绿色。用户因此重复安装、配置或发送请求。

## Decision

复用 activation 状态、配置后的缓存失效、智能体检及脱敏快照，不增加探测服务。两入口共享证据分层与静态处理建议，提供手动刷新状态及就近诊断入口。HTTP 状态不足以断言封禁、余额或上游故障，只指引核对。HTTP 2xx 未确认完成不标为成功；历史成功不能证明当前路由就绪。刷新失败明确标记旧状态。刷新只读既有状态，不发模型请求；详细体检仍为用户主动操作，沿用现有路由维护与修复确认语义。

诊断和生效缓存纳入平台地址、账号、连接状态与同步代际，避免跨账号或跨平台复用。配置保存结束后等待现有刷新结算，不因验收失败重写配置。

## Alternatives considered

- 配置后立即请求模型能直接发现一部分连接问题，但会产生费用、重复请求，且一次成功不保证后续工具执行；本轮仅观察已有请求。
- 新建完整诊断 API 可集中所有状态，但会重复现有采集、脱敏与账户隔离；采用共享展示逻辑与现有体检。
- 仅改成功提示成本低，但用户仍要离开工具卡找报告，且管理页缺少同一验收信息；同时补齐两入口。

## Verification

前端全量 165 个文件、1175 项测试通过，覆盖无配置、无路由、无记录、2xx 未确认、401/403/402/429/5xx、历史成功、刷新失败、直连不可观测及账号边界。针对性 9 个文件 106 项也通过。平台地址或登录状态改变但同步时间不变的测试能阻止旧缓存展示；弹窗打开不发诊断，明确点击才调用原命令，账号变更关闭弹窗。配置操作不增加推理/自动重试。

类型检查、变更文件 Prettier、renderer 构建及差异空白检查通过。构建仍有既有的大 chunk 提示。第一轮全量暴露的组件测试依赖与翻译覆盖缺口已补齐，再跑全量通过。没有修改 Rust、启动原生 App/VM 或调用收费模型；本轮不声称完成原生安装包和外部 Agent 的实际请求验收。

决策笔记校验通过。一次性测试、类型检查和构建均退出；结束时进程检查显示测试/构建残留 0，没有启动常驻预览服务。

## Adversarial review

- 旧成功不再使已停止的当前路由显示就绪；配置时间未知、待重启、未观察到请求不宣称本次调用成功。
- HTTP 2xx 且缺完成证据显示待确认，不显示“调用失败 HTTP 200”；401/403、429、5xx 不凭数字断定封禁、余额或责任方。非 Accio 不再追加可能冲突的旧通用错误文案，Accio 专用生命周期提示保留。
- 刷新失败明确展示上次结果；无状态不能断言无需路由。不支持的平台不显示应用配置建议。请求时间供对照，既有报告仍按快照导出，不自动上传。
- 详细体检沿用原生历史路由维护，入口明确说明，不冒充完全只读；弹窗隐藏凭据轮换、回滚与一键修复，仍可在原入口主动操作。

## Consequences

状态只反映本机可观察请求，不证明官方应用使用哪个配置、工具执行或计费结果。HTTP 状态只能给排查方向，详细原因仍需脱敏日志；真实 Windows、Intel 与安装包验证不由浏览器测试替代。

两入口共用判断与报告，减少重复排查步骤，但工具卡会多占用说明空间；配置结束等待既有缓存刷新完成会增加短暂等待，不改变配置成功或失败的判定。没有新增原生 API、采集字段或账户数据上传，未推送及发布。
