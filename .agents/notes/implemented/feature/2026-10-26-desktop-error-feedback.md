# Agent Note: 客户端主动报错反馈与平台收件箱

Status: implemented

## Problem

工作台模型目录、工具安装或界面异常只有短暂提示。用户需要截图转述，维护者无法稳定获得版本、发生时间和操作上下文。用户要求在客户端直接提交，在元衡平台后台统一查看。

## Existing capabilities and impact

现有智能体检可预览、复制和导出凭据绑定的脱敏快照，见[诊断设计](../../implemented/bug-fix/2026-10-01-claude-windows-diagnostics.md)与[后台写入约束](../../implemented/bug-fix/2026-10-01-diagnostics-review-hardening.md)。这两篇部分重叠但保留原边界；体检包含主动网络检查和路由维护，不能用作自动报错采集。现有 frontendLogger 负责本机日志，Sonner 负责通知；两者均无反馈接收端。平台仓库当前无反馈表或后台入口，需增加独立的最小收件箱，不扩展为客服工单。

## Decision

- 复用 Sonner 的公开 API，通过统一 toast 适配器让普通错误提示提供反馈按钮；主工具栏、登录页和界面崩溃页也有入口。
- 只在本进程保存最多十条已脱敏错误；不读取本机日志、聊天、配置文件或截图。切换账号清空缓存和草稿。版本和系统由原生命令生成。
- 用户填写问题描述并预览实际提交内容后主动提交。固定账号认证接口 POST /api/user/desktop-feedback；expectedUserId 仅在本机防账号切换，不发至服务端。相同请求失败重试沿用 UUID，服务端按账号和 UUID 幂等。
- 平台仅管理员可查看和修改 pending/in_progress/resolved 状态；服务端限制长度、条数、频率并再次脱敏。提交失败保持草稿与复制入口，收到有效回执才显示成功。

## Alternatives considered

- GitHub Issues 可复用仓库和讨论，但需要额外账号且公开内容，用户明确选择平台后台。
- 自动上传完整诊断或日志最省人工，却扩大隐私范围，且体检会发请求并维护配置；采用主动预览的有限错误信息。
- 仅加复制按钮改动小，但无法完成后台统一收集，因此复制仅作为离线补救。

## Verification

普通错误、登录页、崩溃页共用同一弹窗；新增脱敏、容量、账号切换、失败保留、重复点击、幂等重试、有效回执与无 Provider 复制测试。Rust 专项覆盖账号会话、输入格式、固定地址与认证头、失败和成功回执；完整 Rust、前端测试、类型、格式、Clippy、renderer 构建与笔记校验通过。浏览器检查中文登录页、反馈表单、预览、关闭和不可提交状态。平台另有权限、分页筛选、状态修改、幂等及脱敏测试；模拟接口与本地 SQLite 测试不代表生产接收和三数据库真机验收。

## Consequences

文本规则不能识别所有自由文本中的个人信息，界面须提供真实预览及不填写敏感内容的提示。未登录时不能提交到账号接口，可复制报告。旧平台返回接口未就绪时不能误报成功。系统进程硬崩溃或窗口无法渲染不在本轮采集范围。

统一 toast 适配器保留原有调用、既有操作和超时设置；已有错误操作时使用空闲的取消按钮位，两个操作位均占用时仍可从常驻入口查看错误。错误信息仅保留本进程最近十条，不跨重启持久化。新增独立界面不依赖查询 Provider，主界面渲染失败后仍可使用。版本更新同时保留已发布 v0.1.108 的账号目录连接修复。

合并 v0.1.108 后，完整回归暴露 coding_plan 的回环测试只设置 NO_PROXY、未刷新先前建立的连接池，导致本机代理将连接拒绝转换为 HTTP 503。测试初始化现显式刷新代理池，保留原错误通道断言，不改业务请求；串行完整库回归通过。Node 25 的全局 Web Storage 与现有 jsdom fixture 冲突，本机前端回归用 NODE_OPTIONS=--no-experimental-webstorage 运行，未改变项目运行逻辑或测试断言。
