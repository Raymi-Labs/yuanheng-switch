# Agent Note: 图片默认组按模型缺失补充福利组

Status: implemented

## Problem

默认图片组可能不提供用户请求的某个图片模型。用户要求内置图片Skill默认使用“生图和视频”，仅在该组目录没有请求模型时使用有权限的“福利”组。超时、余额、认证或生成错误不能引发跨组重复提交。

## Decision

沿用[图片Skill分组隔离](../../implemented/bug-fix/2026-11-13-image-skill-group.md)的独立单组凭据，每个默认图片连接可附带一枚福利组凭据；两者均关闭平台跨组回退。新凭据使用普通明确group且routing_config为空，验证拒绝任何非空routing_config：当前服务端对普通单组令牌在目录前校验组权限，撤权返回403；带routing_config的令牌可能把撤权过滤为200空目录，不能用作模型缺失证明。用户选择其他图片组仍为单组。Desktop在明确配置时验证两枚凭据并经已有认证管理通道同步Core，数据库/运行时不保存密钥。

Core对默认图片连接先读取真实令牌目录，再按原始请求的精确模型ID选择一枚凭据。主组有模型时始终选择主组；主组目录成功且缺少该模型才查询福利目录。读取失败中止，生成/编辑只提交一次，原始JSON和multipart字节不变。图片目录为两组图片模型并集，同名模型归主组；原有版本/质量排序保持。切号、撤销和请求期间连接变化要在提交前复核。

只扩展内置图片连接、Core凭据同步及图片代理；不修改服务端、聊天统一令牌、Codex原生图片路径或视频创作页。当前内置Skill仍是图片生成/编辑。UI在现有分组处用tooltip说明已启用的福利补充，不增加页面或常驻标签。

Skill更新在同一配置锁内读取已选分组，避免排队前的旧值覆盖用户刚保存的选择。图片凭据操作使用局部有界HTTP读取：每响应2MiB、分页累计8MiB、每页最多100项/最多100页；失败和不完整分页不能被当作令牌不存在。所有响应的错误正文不透传，未知创建结果继续保留pending，不自动重建。

## Existing decisions

[图片Skill分组隔离](../../implemented/bug-fix/2026-11-13-image-skill-group.md)部分重叠：保留每枚凭据单组、显式配置和不借聊天连接，仅扩展默认连接的模型可用范围。统一令牌及平台通用路由决定无关，保持不变。

## Alternatives considered

- 单枚多组令牌直接利用服务端选路：代码最少，但现有服务端也会在渠道临时不可用及重试时更换组，不能保证只因目录缺模型选择福利。
- 脚本自行选择路由：无需代理解析multipart，但直接HTTP调用及旧脚本可能绕过主组优先，目录和生成之间也无法在Core统一检查账号/连接。
- 提交前在Core选择单组凭据：增加目录读取和一枚可选图片凭据，但费用来源明确，生成失败不会在客户端跨组重发。

## Verification

Rust全量2791项通过、13项既有忽略；修复审查意见后的图片专项128项通过。脚本149项、图片组件20项、TypeScript检查及renderer构建通过。合成HTTP覆盖主组优先、福利独有模型、两组无模型、目录401/403/429/5xx/跳转/畸形响应停止，选中凭据后生成401/402/403/429/5xx只提交一次；既有传输超时/截断不重发回归继续通过。JSON和multipart精确模型、重复model/畸形请求拒绝，福利凭据同步/撤销/切号/旧快照拒绝、非默认单组及无SQLite密钥均有测试。新增配置排队和响应资源上限回归通过。

两路独立审查指出的撤权误判、默认组并发覆盖、有界凭据读取和常驻辅助文案问题均已修正并复核。真实Chromium仅配合模拟状态检查中文卡片、tooltip键盘入口及900/430宽度，不读取真实账号。完整Core路由到线上服务未作端到端或收费验收；权限契约基于当前本地服务端源码与普通单组令牌测试，未核实线上部署版本。

GUI/Core入口及lib的Clippy -D warnings检查通过，Rust格式、前端格式、决策记录校验通过。Skill标准校验脚本所需PyYAML在本机与捆绑Python均缺失，使用Node核对未改变的YAML头块、字段限制与未完成占位符，未安装全局依赖。测试结束后清理本轮临时编译目录、依赖链接及预览入口，遗留测试/浏览器/服务进程为零。

## Consequences

令牌目录仅反映平台当前提供的模型目录，不能证明渠道运行健康。目录合并及提交前再次读取增加请求延迟，并多维护一枚福利凭据；换来明确的单次提交组归属。福利目录失败会阻止合并目录的自动选模，显式主组已有模型的请求无需读取福利目录。平台手工改令牌范围需重新配置校验，本方案不自动恢复远端规则；跨设备创建同名令牌的既有边界仍保留。没有操作真实令牌、发起收费生成或发布。
