# Agent Note: 图片作品转视频参考图

Status: implemented

[Muse多图扩展](2026-10-31-muse-long-multireference.md)允许Muse原始WebP及最多4图，切离Muse仍仅保留首图并提示；作品转草稿PNG处理保持。

后续用户确认后，[Omni720p恢复文生视频](2026-10-31-enable-omni-720p.md)；本篇对此型号的未开放描述为当时边界，图生视频限制不变。

## Problem

已有创作入口需要把图片下载后再上传才能生成视频；WebP成品不能直接作为PNG/JPEG参考图，用户难以判断哪个视频模型接受图片。文件头检查无法发现损坏图片，可能让收费请求直到供应商阶段才失败。

## Decision

复用作品读取、账号隔离、下载互斥和模型目录。在已完成的图片记录增加“用作视频参考图”：仅准备草稿，不发送生成请求；从当前授权的参考图视频型号中选择（当前为Muse）。没有可用型号时禁用，不回退文生视频。转换由原生命令完成，仅接受当前账号记录，解码限长/限尺寸；转PNG并将长边限制1536，保持比例不裁剪，输出不超过10MB。草稿显示预览，用户另填运动描述并明确生成。

上传参考图在提交前使用有内存/尺寸上限的真实解码校验，拒绝损坏/伪造和异常尺寸。不同参考图模型切换保留参考图；切到不支持参考图的模型清除并提示，防止暗中当文生提交。模型能力说明就近可见。图像转草稿过程中阻止模型/模式/生成操作，切号/卸载丢弃旧结果。

## Existing note review

[创作入口](../../implemented/feature/2026-10-31-media-studio.md)部分重叠，复用原任务和文件生命周期；[兼容修复](../../implemented/bug-fix/2026-10-31-media-service-compatibility.md)的600秒和禁用型号不改变。服务端验收仍不能由前端模型列表推导。本轮不启用Grok首帧、Veo或Omni720p，不改生产渠道。

## Alternatives considered

- 用户先下载再上传：实现最小，但WebP和重复选择增加新手负担。
- 前端canvas转换：无需新增命令，但高分辨率图片更易占用UI内存；使用原生限额解码与缩放。
- 自动发送图生视频：省一步，但用户尚未确认模型、运动描述及费用；只填草稿。

## Verification

原生媒体17项通过，包括新加的PNG/JPEG/WebP转换到PNG、1800×900等比例缩为1536×768、输出小于10MB、损坏但文件头正确的图片拒绝，以及8193像素边长拒绝。沿用实际POST600秒、禁用型号、无凭据下载、账号和记录隔离回归。尺寸先读header，超过8192边长或16,777,216总像素不解码，decoder再设128MiB分配上限。

前端全量166文件1190项通过，媒体页15项覆盖草稿准备无生成调用、用户确认后带reference调用Muse、没有授权参考图视频型号不调用、准备中锁定选择、切号丢弃旧图、兼容型号保留图片/不兼容清除并提示。类型、renderer构建、GUI/Core Clippy（lib、bins、-D warnings）、Rust格式、Prettier和差异检查通过。最后补上准备完成滚动到表单后重复媒体页回归。没有真实收费生成，不更改其他Agent或生产状态。

最终类型及renderer构建复验通过，笔记检查78篇通过；结束时测试/构建进程为0，未启动常驻开发服务或虚拟机。

## Adversarial review

原生命令只接收当前账号作品ID，拒绝未完成或视频记录；复用下载互斥，prepare期间不能删除。CPU解码/转换通过spawn_blocking，完成后再次检查登录会话。前端防止转换结果覆盖用户同时修改的模型/参考图；卸载和切号均丢弃回调。前端格式/体积检查只是提示边界，实际提交仍由原生再次解码验证。不因准备草稿自动调用付费POST；原图片转换可触发已生成结果的下载GET。

## Consequences

转换可能缩小参考图，这是为编码体积和运行内存设置的上限，保留原作品不覆盖。供应商仍可能调整视频构图和时长；本地验证不能证明所有线上型号或参数已成功。

Grok两款、Snow Grok和Omni1080p继续仅文生；Muse可接受图片；Veo Lite与Omni720p因未完整验收继续关闭。单凭客户端代码无法解决供应商403或证明部署后的首帧协议。正式上线前仍需真实客户端生成验收，不把能力字段冒充全量线上证明。本轮仅本地修改，未推送或发布。
