# Agent Note: 客户端周期汇总使用平台实际用量

Status: implemented

## Problem

统一令牌自动选组后，本地日志不知道最终结算组，因此周期估算显示全部未计价。用户要求同步网页显示，不能把未知估算当零消费。

## Existing capabilities and impact

复用 UsageCostSummary 的日期范围与布局、现有账号登录会话和只读 HTTP 恢复。网页控制台的 GET /api/data/self 返回带退款的结算 summary；GET /api/status 提供单位与换算率，服务端限制单次最多30天。无需修改服务端。对照[本地报价](../bug-fix/2026-10-17-request-group-usage.md)和[统一令牌](../architecture/2026-11-08-account-shared-token.md)：只替换周期卡，不把本地请求明细伪装成平台账单；报价目录仍位于定价配置中。

## Decision

卡片置于本地筛选之前，标题平台用量，当前账号全部设备；消费、请求数和Token来自同一服务端summary，单位和换算率也来自平台配置。只读本人接口，不传任意账号或管理员查询条件；请求前后检查登录身份。查询缓存按账号、域名及时间范围隔离；查询交由原生网络执行，不受浏览器 offline 暂停机制影响。断网、缺少summary或切号不显示旧金额为当前数据。失败显示“暂未同步”及可用的重试按钮，超过30天显式提示调整时间，不回退估算或伪造零值。

账号客户端禁止跟随重定向，调用规范无尾斜杠路径。金额解析保留净退款，按平台当前单位换算；显示前沿用网页 toFixed(2) 规则和正微小消费最低显示值，再做本地化分隔。平台自动刷新至少间隔30秒，后台不轮询；手动刷新不改变任何令牌或账单。

## Alternatives considered

- 用本地请求组套倍率：无法知道平台路由结果，不能达到与网页相同的结算口径。
- 将网页嵌入客户端：登录和导航重复；原生页面已有可用汇总与日期控件。
- 按时间拼接本地日志与平台账单：没有逐笔关联证据，容易错配其他设备请求。

## Verification

先通过旧卡测试复现仍显示本地近似金额；新卡读取同一模拟平台 summary。原生4项覆盖单位换算、负值退款、空字段、30天边界、规范路径和禁止重定向的HTTP夹具、请求中途换号。前端23项覆盖读数、时间与刷新、首次失败、切号/退出/域名变化、断网错误、浏览器offline以及±1.005舍入；offline和舍入用例修复前失败、修复后通过。类型、格式、renderer构建通过。独立规范及规格审查补齐数据源地图，并修复路径、offline与舍入问题。

真实组件用模拟数据在 Chromium headless 渲染浅色1440×900、深色900×600及英文失败/日文退款状态，无横向溢出、页面错误；临时浏览器和预览服务退出。不读取真实客户账单、不发收费请求，此验证不代表已对线上账号逐项对账。

## Consequences

[净消费精度修复](../bug-fix/2026-11-17-platform-usage-precision.md)替代“沿用网页 toFixed 和微小消费最低显示值”的决定：改为保留平台金额精度，明确净消费与日志扣费总额的区别，不以表面数值一致代替口径一致。

后续用户明确要求已有数据保留：[数据可用性修复](../bug-fix/2026-11-17-usage-data-availability.md)替代“暂时刷新失败隐藏缓存”的显示决定。现在同账号同范围临时失败保留标注时刻的快照，部分字段可用时分别显示；鉴权、身份及范围异常仍不混用。

数值是账号全部设备，不能受本机Agent/供应商筛选影响。依赖已部署的结算summary接口；旧服务端或保留期外数据不自行估算。平台缓存和查询时刻差异仍会影响刷新瞬间数值。
