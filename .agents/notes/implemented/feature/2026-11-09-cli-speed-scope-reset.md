# Agent Note: 用户切换配置时自动回标准

Status: implemented

## Problem

要求用户在切换至不支持加速的分组后再次手动选标准，增加无必要操作。用户明确要求客户端自动切换，取代此前保留失效选择并阻止启动的界面策略。

## Decision

切换到同样支持的模型/分组也重置这一策略，已由[按能力保留](2026-11-09-cli-speed-capability-retention.md)部分取代；换账号仍重置、在途请求仍不改档。

账号、模型、分组或工具作用域变化后，待启动的速度选择自动回标准，并以短暂提示说明。首个渲染即丢弃旧作用域的付费参数，不等异步查询结束；迟到响应不能恢复旧选择。未切换作用域的能力撤销或网络错误仍保留拒发，不自动重发。已经启动的付费连接和在途请求不改变。

此决定部分取代[CLI启动速度选择](2026-11-09-cli-launch-speed-picker.md)的失效选择交互；连接票据、后端校验及费用隔离保持原约定。

## Alternatives considered

- 保留失效选择并要求手动标准：明确但多一步，用户已否决。
- 所有错误都自动降档重发：可能重复收费且改变已提交请求，不采用。
- 仅用户主动切换作用域时自动标准：消除额外操作，不改变已提交请求，采用。

## Consequences

切换到同样支持加速的分组也从标准开始，不跨配置继承付费默认。提示不是确认框，不阻塞启动。相关组件和Hook测试覆盖自动隐藏、启动可用、旧响应不恢复付费参数；没有改动原生层或执行收费请求。
