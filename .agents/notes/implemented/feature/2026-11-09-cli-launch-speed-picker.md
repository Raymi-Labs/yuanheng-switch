# Agent Note: Codex CLI 本次启动速度选择

Status: implemented

## Problem

原生目录支持档位不等于用户能在元衡选择并确认本次CLI请求。当前CLI连接共享桥接，直接修改全局配置会让其他终端承担付费默认。

## Decision

启动后重置和模型/分组切换交互现由[按能力保留](2026-11-09-cli-speed-capability-retention.md)部分取代；成功启动保留选择并显示最近启动档位。

用户主动切换配置后的失效选择交互已由[自动回标准](2026-11-09-cli-speed-scope-reset.md)部分取代；下述保留失效选择的初始决定不再适用于主动切换账号/模型/分组。

速度入口只在当前账号/分组/精确模型返回至少一个付费档位时显示；查询中、失败或仅标准时隐藏，推理等级恢复整行。已选付费档位随后失效则保留选择与错误提示并阻止启动，用户明确改回标准后收起，不静默降档。复用现有重新检测/重新选择触发能力查询，不新增后台轮询。

复用已有能力接口及Core守卫，在工作台推理等级旁增加本次启动速度。选择仅存组件内存，账号/模型/分组变化保留失效状态并阻止付费启动，成功启动后重置标准。启动后端再次查询能力并核对本地配置，桥接用一次性启动票据把档位绑定单个连接；付费连接只允许新线程，逐轮校验账号/模型/分组不变，不改全局默认或其他终端。标准连接仍保持原生菜单行为。

现有desktop-native-service-tiers笔记继续拥有目录和Core协议，本篇仅补工作台启动入口。现有本地日志不证明服务端最终结算，不标记“已按六倍扣费”；费用确认继续查看服务端使用日志。

## Alternatives considered

- 写全局service_tier：实现简单，但会污染其他会话费用，拒绝。
- 只拼TUI启动参数：不保证remote桥接转发行为，拒绝。
- 连接级一次性票据：能明确隔离，采用；断线重新启动需再次选择。

## Verification

前端64项相关测试验证作用域失效、迟到响应、离线重试、选择到启动参数和成功重置；类型及renderer构建通过。11项桥接测试包含真实WebSocket与假CLI子进程，验证ultrafast逐轮注入、票据重放拒绝、换账号后拒发并等待子进程退出；Clippy lib/bins通过。宽1280/窄430真实FocusToolCard以合成账号渲染，无页面错误及横向溢出。官方app-server另用既有7请求脚本复核参数和不重试；不等同完整GUI启动官方CLI的端到端验收。

## Consequences

本轮不宣称真实Windows终端点击验收、官方桌面GUI入口或结算闭环。付费启动范围固定，新建对话仍保留该连接档位；恢复旧会话必须改用标准启动以免旧会话收费策略被覆盖。

终端profile明确传递标准默认和零重试，付费档位只覆盖独立连接启动的子进程。一次性票据120秒过期、最多32条；未启动终端的票据只占有界内存，下次签发清除过期项。其他Agent继续原有启动入口。用户没有授权推送或发布，本次仅保留本地变更。
