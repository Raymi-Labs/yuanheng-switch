# Agent Note: 跨入口安装进度与等待可见性

Status: implemented

## Problem

安装已有共享互斥、取消和验证，但界面只转圈。DSH 下载运行时、校验、解压、安装包的实际阶段未暴露，用户无法判断是否仍有进展。

## Decision

复用 toolLifecycleState 和原生进程监督器，使用每次 IPC 独立的 Tauri Channel 传递白名单阶段、下载字节与输出活动信号，不传原始输出、路径、请求头或凭据。任务闭包隔离迟到消息。DSH 从受控 staging 中读取阶段、归档大小和响应的 Content-Length；只在字节总量有效时显示下载百分比，其余阶段使用不确定进度条。所有入口共享任务开始时间和最后活动时间；静默超过一分钟提示没有新的进度，不能断言进程卡死。

官网下载安装显示等待用户完成安装和本机检测，不声称掌握外部浏览器下载进度。Claude Windows 准备流程继续复用自身状态。

## Alternatives considered

- 按时间递增百分比容易理解，但会把无进展显示成推进，不能采用。
- 全部改为 Rust 下载器能统一字节流，但重写所有官方安装器超出本次范围；复用已有受控脚本和输出排空器。
- 原始终端日志信息丰富，但可能泄露代理凭据、路径和 npm 配置；仅传递固定枚举与活动信号。

## Verification

前端 965 项测试通过，含共享进度、有效/未知下载大小、静默提示、活动恢复、取消时迟到进度、失败清理与重试隔离。Rust 回归覆盖受控子进程、真实下载文件增长/阶段传输、输出活动与敏感内容不进入 IPC；取消、超时和进程树回收继续通过。TypeScript、renderer 构建与 Clippy 通过。

真实 App 壳使用模拟 IPC 在浏览器验收工作台/工具页切换保留字节与时间、阶段切换、取消、失败重试、DSH 更新成功清理、普通 CLI 与官网安装等待、暗色和 900×600 窗口。模拟版本与字节不代表真实下载；没有修改用户工具安装或凭据。Windows 真实官方下载仍需独立环境验收，三平台 CI 校验编译与进程回归。

## Consequences

原生安装显示有依据的阶段、下载量和最近活动。每 500 毫秒最多发一次进度，保持 stdout/stderr 各 64 KiB 的既有边界；结束后停发并清理共享状态，原有验证完成才解锁。DSH Unix 下载从受控响应头读取总量，Windows 在没有总量时显示已写入文件大小及不确定进度。未知阶段、安装器输出、路径与响应头本身不进入界面。

第三方脚本不提供统一阶段或总大小时，仅显示执行活动和耗时；官网安装与 Claude Windows 准备保留自身观察/系统状态，不能据进度条推断下载成功。静默一分钟只是提醒，不等同卡死，也不自动重试或改变既有取消和超时边界。浏览器观察的耗时从当前入口开始，原生安装耗时跨页面共享。
