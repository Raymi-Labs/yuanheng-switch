# Agent Note: Codex 首次配置登录指引

Status: implemented

## Problem

首次配置 Codex App 后，用户仍需在登录界面输入 API Key，却不知道配置过程已经准备了平台令牌，因而重复打开平台创建和复制令牌。

## Decision

复用 configure_yuanheng_tools 的现有分组令牌与配置事务。共享前端 configureTools 在桌面 Codex 配置成功后调用只读指引命令，缺少本地登录材料且桌面托管路由有效时显示当前工具令牌、复制按钮与 API Key 登录步骤。等待用户关闭指引后继续安装/启动链。读取失败单独提示，不把已保存配置报告成失败。

令牌只进入弹窗短期状态，不进入配置结果、查询缓存、日志或本地存储；关闭、断开、切号和卸载时丢弃。请求绑定发起配置时的 UI 账号，后端再核对账号和有效会话；指引不创建令牌、不写 Codex 登录文件。已有登录材料时不自动弹出；尚未登录时重新应用配置可再查看。

## Existing decisions

[首次配置标记恢复](../../implemented/bug-fix/2026-10-14-codex-surface-mode-repair.md)部分重叠，保留桌面/终端隔离和官方登录保护。[通用凭据修复](../../implemented/bug-fix/2026-11-02-credential-group-repair.md)部分重叠，沿用现有按组创建、复用和不确定结果保护。会话同步、图像技能笔记不负责首次登录 UI。

## Alternatives considered

- 在弹窗另建令牌：易于获得密钥，但重复创建且可能与工具所选分组不一致，改为读取本次配置的托管凭据。
- 自动写 auth.json 绕过登录：用户步骤更少，但会侵犯官方登录文件所有权，不采用。
- 各工具卡分别加指引：局部容易实现，但会遗漏工作台、批量和安装续接入口，改在共享 API 承接。

## Verification

新增前端回归验证复制、已有登录跳过、失败/非桌面配置跳过、切号迟到结果丢弃、关闭清理和复制失败。完整 App 工具管理流程分别覆盖首次登录弹窗与已有登录，两者关闭/跳过后都能继续启动；相关前端50项通过。原生2项测试使用临时 HOME、模拟账号和真实配置函数，核对桌面分组令牌、官方登录文件保留、异常 JSON 拒绝和旧账号凭据不回显。Codex 相关551项通过、2项原有忽略；Clippy lib/bins warnings-as-errors通过。

完整前端171文件/1265项、TypeScript、renderer构建、原生bins检查、格式、版本公告及笔记门禁全部通过。Playwright以模拟令牌渲染实际组件，核对桌面弹窗排版与复制按钮反馈；预览未访问真实账号或创建令牌。发布脚本Node测试与Python release工具测试通过。

## Consequences

用户无需再手动创建令牌；同一配置/启动调用在弹窗关闭前等待，关闭可稍后登录。令牌复用现有工具记录，新增非敏感账号归属字段只用于指引核对；旧记录需要显式重配后才允许显示。平台计费分组与凭据创建策略保持现状。

本地 auth.json 只提供可观察的登录材料，不能证明服务端登录有效性或外部钥匙串状态；读取未知状态时不猜测。未执行真实第三方客户端全新登录，不将模拟测试当作 Windows/macOS 新设备验收。
