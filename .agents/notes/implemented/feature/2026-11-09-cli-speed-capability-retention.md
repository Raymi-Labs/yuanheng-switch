# Agent Note: 根据能力保留速度选择并自动刷新

Status: implemented

## Problem

用户需要一个可选速度入口，而不是在每次切组或启动后重复选择。不同价格分组可能拥有相同的加速渠道，不能把鹈鹕王或企业名称写成能力判断。启动后立即显示标准还会误导用户认为已启动终端降档。

## Decision

同一账号在当前挂载的工作台中保留速度偏好。模型/分组改变时立即停止使用旧能力，等待当前作用域查询；仍支持则保留偏好，明确不支持则自动标准并短暂提示。换账号或离开CLI作用域清除付费偏好和最近启动记录。网络错误不等同不支持，付费选择保持但不能启动；后续聚焦/恢复网络自动重新查询。

进入页面、模型/分组/账号改变、窗口重新聚焦、页面恢复可见、网络恢复时查询；相邻焦点事件150ms合并，卸载清理定时器和监听，不周期轮询。启动后端仍实时核对能力与配置，配置和档位由元衡自动传入。查询结果只属于发起时作用域，迟到结果不能覆盖当前结果。

成功启动不清除选择，并在该作用域显示“最近启动”档位，修改下次选择不会改变该记录或既有终端。此信息不是请求成功或扣费确认；客户端没有可靠结算关联时仍使用服务端日志，不生成虚假费用状态。

本决定部分取代[切换即标准](2026-11-09-cli-speed-scope-reset.md)及[启动后重置](2026-11-09-cli-launch-speed-picker.md)。后端连接票据、单连接付费范围、拒绝旧会话恢复、已发请求不自动降档重发保持不变。

## Alternatives considered

- 切组一律标准：安全但对同样支持原档位的企业等分组造成重复操作，不采用。
- 继承档位而不重查：操作少但不能证明新分组权限或渠道支持，不采用。
- 查询后有条件保留：符合用户选择且保留授权边界，采用；查询失败时仍需要等待或明确标准。

## Consequences

偏好只在当前页面内存中保存，不跨账号、应用重启或会话写全局默认；最近启动记录不代表终端仍存活。68项前端相关测试和类型检查通过，覆盖企业分组/模型切换保留、无能力回标准、离线不降档、迟到响应、聚焦合并刷新、卸载监听清理、选择变化取消旧启动及启动后保留显示。本轮未调用真实模型、未改渠道、未推送发布。
