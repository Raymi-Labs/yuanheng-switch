# Agent Note: Accio 已验证版本的本地客户端入口

Status: implemented

## Problem

0.35.3已在干净macOS VM取得用户正常使用回执和sol/luna真实转发记录，但产品启动器仍只接受0.34.5，配置动作又早于版本/签名检查。用户可能先得到配置成功提示，再被启动门禁拒绝，或普通打开官方应用而误以为已走元衡。测试脚本不是产品入口，状态也不能由磁盘active或历史HTTP200单独推断。

## Decision

复用现有工具管理、工作台、官方应用发现及Core持有Child的启动链。[installation.rs](../../../../src-tauri/src/accio_work/installation.rs)统一0.34.5与0.35.3精确受控版本，配置/模型预检在联网创建凭据与落盘前核验签名和版本，配置写入前复检所选路径，Core启动时再次核验，不信任前端缓存。轮询只读取廉价版本提示，不反复执行完整签名检查。失效自定义路径明确要求重新选择，不静默改用另一份应用。

工具管理和工作台共用连接说明及原有生效进度：配置保存、Core受控启动、模型输出分别表示。客户端设置默认模型，Accio显式选择由其原生菜单控制，Auto只解析到元衡默认值。当前路由未持有活进程、旧账号/分组记录或零输出不作本次成功证据。普通启动仍不接管，已运行应用不强杀，未知版本明确失败。

本地请求日志复用既有session_id字段，写入capability、owner、group的长度前缀SHA-256标记。此摘要不是访问能力，不可授权，不作为上游客户端会话/缓存key发送；每次受控启动、账号/分组变化使标记变化。同一运行内改默认模型保留标记，显式菜单模型继续可用。生效查询限定标记、入口、配置时间和managed provider，输出tokens>0且当前路由活跃才确认成功。无schema迁移，也不改变其他Agent的默认查询；旧Accio日志保留用于历史账单但不冒充新启动成功。

保留默认关闭与实验发布包保护，只完成本地产品路径，不发布、不修改宿主现有服务。0.35.2维持测试入口范围。本地debug应用打包到专用VM，使用现有账号配置，更新前确认无活跃请求并可恢复备份旧应用。完整原生界面/工具验收与产品Core检查分别记录。

## Existing decisions

- [主模型桥接](../../proposed/feature/2026-10-18-accio-primary-model-bridge.md)部分重叠：保留协议/分组/官方身份端点边界；本篇接管版本列表与配置前检查的产品入口，旧版限制的历史证据保留。
- [Core进程所有权](../bug-fix/2026-10-19-accio-core-process-ownership.md)继续有效，不改成磁盘active或同名进程接管。
- [干净Mac验收](../../proposed/testing/2026-10-19-accio-clean-macos-vm.md)记录测试环境；其中UI工具受限不构成放宽验收结论的依据。

## Alternatives considered

- 继续只用手动测试入口：隔离最强，但不能满足客户端一键配置与启动目标，用户也容易误开官方线路。
- 仅把版本判断改成任意0.35.x：改动少、更新后看似可用，但未检查协议的版本会进入真实模型通道，拒绝采用。
- 配置后再签名/版本检查：复用现状成本低，却会制造成功提示、令牌副作用与启动失败的不一致；提前检查并在Core重复核验。
- 使用已有生效进度：可同时覆盖工作台与工具卡，代价是要明确历史调用与当前受控进程的区别；不新增另一套代理或状态存储。

## Verification

相关前端74项、全量前端982项通过，TypeScript与renderer构建通过。Accio Rust42项覆盖精确版本、未签名同名包、账号/分组/启动摘要变化、scoped查询、零输出文案、进程所有权和三协议往返；另有Codex生效链回归通过。真实隔离Core测试确认孤立active拒绝、重复Core无副作用、外部Origin拒绝、崩溃重启不复活旧地址及连接器退避，模型请求0并清理进程。

专用VM中实际产品Core管理接口启动官方0.35.3返回200、重复启动409，父子关系为Core→Accio、能力令牌轮换、7模型目录与配置一致。确认活跃连接0后退出，旧能力401、route/active撤销、Accio/helpers为0；guest正常关机，宿主受保护配置哈希另行核对。本轮未新增模型推理，0.35.3的真实sol/luna依据仍为用户先前的5条转发记录与回执，不冒充本轮GUI三段切换。

新debug GUI实际显示需要恢复钥匙串登录访问，Core子进程另触发局域网权限提示，未绕过或代替用户授权。完整GUI配置→启动→原生三段切换及0353工具往返仍未新增验收；已安装包与配置保留，原包可恢复。没有发布或承诺跨系统完整支持。

用户随后亲自通过产品GUI启动并取得sol/luna回复，当前启动scope记录匹配；进一步合成文件读取返回了未放入提示的正确随机marker。写入相关两轮在上游流错误后终止、未产生文件，当前不宣称全量文件工具通过。固定只读云端连接器查询仍明确501。此后续证据不改变入口实现范围，产品默认关闭/发布保护保持，错误诊断和写入复验为下一独立工作。

## Consequences

后续用户已要求首版试用发布。仅对已验证Apple Silicon平台放开构建的候选方案与最终验收归属[实验发布范围](../../proposed/feature/2026-10-27-agent-experimental-release.md)；该提案未完成前，本篇历史debug验收不构成正式发布成功。

配置前失败更早、当前运行状态更准确，代价是显式配置/启动要执行签名检查，旧Accio历史成功不会点亮新运行的成功状态；同一运行的请求归于本地启动范围，不能拿它当官方会话标识。官方更新可能改变进程或网关协议，精确版本要求元衡后续适配；签名校验不是完整沙箱。官方登录/遥测及模型上下文仍可能包含VM设备或工作区信息，保持已披露的隔离边界，不使用宿主个人工作区。默认功能开关仍须前端、GUI和Core一致，本地debug包不是签名公证发布包；系统授权与剩余GUI验收仍为明确限制。
