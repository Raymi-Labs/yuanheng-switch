# Agent Note: 账号模型目录连接与有限恢复

Status: implemented

## Problem

DSH 安装完成后会继续执行账号分组预检，`/api/user/models` 的传输错误会阻止配置和启动。账号客户端独立创建 reqwest Client，未使用应用全局代理，没有只读请求恢复，并将带 URL 的笼统错误直接展示；截图只能证明该请求传输失败，无法判定客户电脑上的 DNS、TLS 或代理原因。

## Decision

账号控制面复用现有全局代理配置、系统快照与连接池更新机制，保留独立 15 秒请求上限、禁止重定向和隐式重试。账号同步、分组模型预检和令牌模型目录 GET 只在可恢复传输错误时等待 200 毫秒后最多重试一次，第二次仍使用同一地址与认证上下文；响应体中断也受此上限约束。HTTP/业务/解析错误、TLS 与代理认证隧道错误不触发重试。未识别的连接错误也不重试，避免 Windows 本地化证书错误被当成瞬时失败。POST 不重放。

复用现有脱敏网络分类，展示中文原因与恢复提示，不输出请求 URL、组名 query、账号、Cookie、令牌或原始错误链。保留实时目录检查，错误不能通过缓存、换组或跨域降级成成功。前端继续由已有手动启动入口重试，安装成功不代表配置成功。

## Existing capabilities and note audit

- 工作台与工具页共用预检、配置和启动；无需创建 DSH 专用网络流程。影响登录/刷新/目录预检/配置所用的账号客户端，以及使用同一客户端的图像分组读取。
- [出站连接池与诊断](../../implemented/bug-fix/2026-10-12-outbound-connection-stability.md)部分重叠，复用代理和诊断机制；其模型转发不重放约束保持。
- [客户端选路](../../implemented/architecture/2026-10-17-client-route-selection.md)部分重叠，账号控制面继续使用既有地址，不引入文本模型选路和跨线重试。
- [工作台安装](../../implemented/bug-fix/2026-10-17-workspace-direct-install.md)部分重叠，安装后续接、账号/卸载保护不变；不存在需要归档的同题笔记。

## Alternatives considered

- 仅把错误翻译成中文：改动最少，但绕过应用代理以及瞬时断线不能恢复的问题依然存在。
- 预检失败时用缓存直接配置：可在离线时继续，但可能放行已撤销的分组或模型权限；保留实时校验。
- 所有请求自动重试或切换官方域名：能够绕过部分故障，但登录、令牌创建等写操作可能重复，控制面认证也不属于模型线路策略；只重试同地址的只读 GET。

## Verification

- 实际本地 TCP 服务验证首个连接/正文中断后恢复、连续失败最多两次、HTTP/业务/解析/重定向不重试、POST 不重试。中文与特殊字符分组、Cookie 和用户标识在重试中保持一致；错误不泄漏敏感原文。
- 模拟代理验证账号请求遵循显式代理及配置更新，稳定配置复用连接，无效更新保留旧池。真实延迟响应确认账号总超时仍为 15 秒，没有继承模型转发的 600 秒。
- 新增前端测试验证 DSH 安装后预检失败不配置/启动，保留安装，手动重试成功才续接；单纯检测和重新检测不自动配置。
- 全量前端 153 文件、1,025 项通过。Node 25 运行需 `NODE_OPTIONS=--no-experimental-webstorage`，否则原生 localStorage 干扰既有测试替身。Rust 2,486 项单元测试和 116 项集成测试通过，3 项既有忽略；测试运行给 loopback 设置 NO_PROXY，避免系统代理把既有“本机端口拒绝连接”用例变成 HTTP 503。
- 类型、前端格式、Rust 格式、Clippy、renderer 与 Core 构建、版本公告与笔记校验通过。三平台签名发布由现有工作流核验；本地验证不代表客户电脑的真实网络或 Windows 真机验收。
- v0.1.108 的云端 Windows/Linux Clippy 暴露原有 `Duration` 导入在本次移走超时构建后仅用于 macOS；导入随使用方限定 macOS。v0.1.109 的测试编译进一步暴露图像分组测试对该类型的间接依赖，由 `6a17f55c` 改为测试模块显式导入。两个候选版均在公开前取消，不改写已推送标签；修复随后续统一版本分发。
- 合入统一主分支后的 Windows CI 已通过本修复新增的 10 项账号传输/连接池/脱敏用例。统一版本 v0.1.111 的其他 [Core 恢复](2026-10-26-core-health-recovery.md)端口探测用例失败由该能力继续处理，不能将本模块测试通过描述为整版发布成功。
- [v0.1.110](https://github.com/nanashiwang/yuanheng-switch/releases/tag/v0.1.110) 已包含 `7cd5e720` / `7a9e7270` 的完整运行时代码；账号 HTTP、共享代理和错误分类与后续通过相关测试的主分支一致。[发布流程](https://github.com/nanashiwang/yuanheng-switch/actions/runs/40284750783) 的三平台构建、Mac 签名公证、集中发布及 R2/平台分发全部成功。2026-10-26 核验 GitHub 正式版 9 个附件均已上传且有 SHA-256，线上更新清单版本为 0.1.110、6 个平台键均有签名。本结果不把旧标签上测试模块缺失导入导致的 CI 失败说成通过，也不替代客户现场网络验收。

## Consequences

一次恢复会增加失败等待，最多两次各 15 秒加 200 毫秒退避。持续不可达仍需修复客户网络，开发机验证不能证明截图电脑的网络已恢复；三平台打包与真机验收分开记录。账号客户端获取时核对系统代理快照，GUI 不依赖独立 Core 的刷新循环。图像分组读取共用代理与超时，但仍沿用自己的 2 MiB 正文上限与事务校验；模型推理、图片生成不新增重试。
