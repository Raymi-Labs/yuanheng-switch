# Agent Note: Core 健康探测失败时保留存活服务

Status: implemented

## Problem

桌面每五秒读取 Core 状态。查询失败后恢复逻辑再次查询，仍失败便激活二进制并在 macOS 对已注册服务执行 bootout/bootstrap。短暂状态故障因此会终止正在处理请求的 Core，bootstrap 失败又延长停服；原始探测错误被丢弃，日志只能看到恢复失败。用户看到本地代理空正文 503，难以区分本机与上游故障。

## Existing capabilities and impact

复用 [CoreSupervisor](../../../../src-tauri/src/core_daemon.rs)、[巡检服务](../../../../src-tauri/src/services/proxy.rs)、[桌面巡检入口](../../../../src-tauri/src/lib.rs) 和既有独立 Core。正常升级已检查活跃请求、保留旧二进制；显式配置目录迁移在重启前 stop 旧服务，不需要巡检猜测并卸载。

已检索活跃笔记中的 core_daemon、健康、launchctl、后台恢复：没有现存巡检恢复决定；[出站连接稳定性](../../implemented/bug-fix/2026-10-12-outbound-connection-stability.md) 涉及上游连接池，属于不同恢复范围，不改变其决策；[诊断加固](../../implemented/bug-fix/2026-10-01-diagnostics-review-hardening.md) 只涉及请求诊断写入，保持独立。本次扩展现有生命周期，不新增守护进程或前端配置。

## Decision

- 健康查询失败保留安全的错误阶段、原因和耗时；禁止跟随管理接口重定向，不记录凭据或响应正文。
- 自动启动及升级回退前核验运行记录中的 PID 和候选监听端口。存在存活进程、仍监听或状态未知时保留 current 和现有服务，返回可诊断错误；仅确认无运行迹象才启动。
- TCP 候选地址使用最多 5 秒的并发探测，完整收集各地址的明确拒绝、监听或未知证据；存在监听优先报告，任意未知仍禁止恢复。短预算或首个地址提前返回不能代表全部候选端口的状态。
- macOS 已注册服务禁止自动 bootout。核验归属后以不带 -k 的 kickstart 启动，未注册时才 bootstrap；bootstrap 失败有界重查/退避，不能通过停止服务来重试。配置不匹配要求走明确迁移入口。
- 巡检在连续失败后才尝试恢复，维护共享的指数退避，成功后重置；定时器跳过积压 tick。手动启动仍保留上述存活保护。
- 正常升级继续采用现有空闲检查和回滚合同，不承诺新请求进入与停机之间的严格零中断，也不新增模型请求重放。

## Alternatives considered

- **只延长超时或增加重试次数**：改动小且可减少误判，但任何最终失败仍能终止存活服务，不能消除故障放大。
- **350 毫秒探测并在首个未知结果返回**：等待短，但 Windows 全量回归暴露了该预算和候选提前返回的不足；当时断言未记录底层错误，不能断言具体 Winsock 原因。并发的 5 秒上限保留有界等待，并完整核验全部候选。
- **禁用所有巡检恢复**：立即避免误杀，但会失去退出恢复与延后升级；保留探测和保守恢复能兼顾两者。
- **持续失败后强制重启存活进程**：可自动解除真正死锁，但状态查询无法证明推理也停滞，可能切断活跃 SSE。存活但不可管理时保留进程并明确报错，显式重启仍可用。

## Verification

- Rust `cargo test --lib core_ -- --test-threads=1` 通过 45 项，包含状态 500、损坏 JSON、3 秒超时但 TCP 仍监听、延迟连接拒绝、多候选并发与未知拒恢复、活 PID 无监听、损坏运行记录、升级回退保护、重定向与 launchd 模拟。断言旧 current/versions 不变，launchctl 全由注入模拟执行，不触及本机服务。
- 共享巡检回归验证 5/10/20/40/60 秒上限、恢复归零、克隆跳过探测；健康失败计数独立于路由刷新错误。测试复用隔离 settings 与 HERMES_HOME 的临时目录。
- 合入当前主分支后前端类型检查、1043 项测试、renderer 构建和发布版本检查通过。本机 Node 25 的测试关闭实验性全局 Web Storage，与 CI Node 20 的 jsdom 存储语义保持一致。
- 笔记结构检查通过。三平台构建及真实签名安装的结果需以正式发布 run 验证，模拟 launchctl 不代替 Windows/macOS 真机验证。

## Consequences

管理探测故障不再授予停止进程或覆盖 current 的权限；退出恢复仍复用原有系统守护和版本安装。日志保留阶段与耗时，但不包含请求正文、凭据或任意响应文本。管理接口禁止重定向，不影响模型转发策略。

保守恢复不会自动杀死真正卡死但仍存活的 Core，需要显式重启。PID 复用、端口被其他程序占用、损坏运行记录或未知系统状态同样会阻止自动启动；这比误杀或覆盖已有实例安全。端口证据最坏等待 5 秒，退避会推迟未受系统守护的真正退出恢复；健康巡检成功时不运行这些探测。正常空闲升级保留既有活跃请求检查，不承诺并发到达请求的严格零中断，也不重放模型请求。发布不等于本机已运行新版，需分别验证 GUI、Core 版本和监听状态。
