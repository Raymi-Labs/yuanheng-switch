# Agent Note: 托管推理档位一致性与旧目录更新

Status: implemented

后续：[平台逐型号声明](../feature/2026-11-18-platform-reasoning-profiles.md)在有声明时优先；本篇内置规则保留为离线兼容，原有目录所有权及显式选择保护继续适用。

## Problem

同一模型的档位取决于机器上的 Codex 缓存。空缓存下 gpt-6.1-sol 回退只有 low/medium/high/xhigh，已有完整目录的机器显示 max/ultra。旧目录更新只检查模型名单不足以识别能力变化，直接修改生成文件会被覆盖。

## Existing capabilities and impact

复用 model_reasoning.rs、Codex 内容哈希目录、托管供应商拥有权及配置原子写入。工作台通过 connection.reasoningLevels 读档位。[窗口与旧字段迁移](../../implemented/bug-fix/2026-10-16-codex-context-and-obsolete-setting.md) 部分重叠，保留自定义配置及回滚边界。本轮不改变账号、默认模型或默认推理选择。

## Decision

托管目录使用确定的内置能力规则，补齐已有 Codex 元数据及会话模型能力声明支持的 gpt-6.1-sol；未知型号沿用保守回退，不按 GPT 前缀开放 Ultra。自定义供应商仍优先显式声明。界面和生成目录共用规则，启动/刷新只更新当前账号、元衡拥有且仍活跃的目录。未标来源的显式用户档位保留；只替换自有来源或原来缺失的默认声明。生成新文件后只换目录指针，保留选择及其他配置，失败保留旧指针。不把客户端修复称为平台热同步或上游执行验收。

## Alternatives considered

- 只修改用户 JSON：立即可选，但重配覆盖，无法修复新安装。
- 所有 GPT 开放 Ultra：统一简单，但不支持的模型会收到无效参数。
- 完全依赖本机缓存：方便但新安装与旧缓存机器不一致。
- 本地统一规则及安全迁移：可离线验证；平台能力服务仍需单独实现、验收及发布。

## Verification

隔离 harness 直接编译生产 model_reasoning 模块，空缓存 gpt-6.1-sol 回归先失败（四档对六档），修复后通过。生产 Rust 测试覆盖同一入口，并覆盖旧声明投影、显式用户声明保留、未知型号不开放 Ultra、脏缓存下真实 Codex 目录生成、双端指针变化与 auth/模型/强度/上下文/注释保留、幂等、其他账号/外部路由保护、第二端目录损坏不部分提交、第二端数据库失败恢复第一端配置、不兼容已选档位及符号链接拒绝。测试使用临时目录、合成凭据和内存数据库，测试凭据库为内存替身。

Codex 相关回归 664 项通过、3 项原有忽略；元衡配置相关回归 218 项通过。生产库与 binaries 的 Clippy（-D warnings）通过。最终推理相关回归 98 项通过；最终生产库及 binaries 的 Clippy（-D warnings）通过。Rust 格式、差异空白及笔记树/格式/归档三项检查通过。目录来源标记同时写入生成结果并在读回时恢复，避免生成值被当成显式用户覆盖后永久冻结。没有运行已安装应用或真实上游请求；未发布安装包。


## Consequences

当前后端未提供完整逐模型档位，内置规则仍需维护，不能保证未来型号及所有渠道。已有会话可能需重新打开；新增档位不自动提高用户强度，也不证明上游执行 Ultra。


## Adversarial review

迁移不以文件名或 Core 存活作为拥有权证据：同时核对账号、provider category/current/surface、回环路由、托管目录路径及符号链接。写入前重读文件和 DB，写入后复核账号；回滚只覆盖仍等于本轮结果的数据，保留外部并发修改。文件准备与发布分离，第二端准备失败不切换第一端；原目录保留供回滚。未标记来源的显式声明可能是用户限制，不自动扩展，需显式重配或后续平台来源迁移。自动修复只在启动/刷新运行，没有轮询重写或自动收费重试。

平台能力服务、按渠道/分组声明、端到端付费请求和 Windows 真机仍是后续阶段。本轮内置规则不宣称新平台接口已经上线，也不承诺所有未来型号自动获得正确能力。源声明同步仍须单独实施；未知型号继续保守处理。

临时独立测试 harness、该工作区首次误建的 target 及复用 sidecar 的临时符号链接已清理。最终进程检查 cargo/rustc/测试二进制均为零；未启动 GUI、开发服务器或虚拟机。
