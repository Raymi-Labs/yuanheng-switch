# Agent Note: 通用凭据与有效分组修复

Status: implemented

## Problem

账号所属分组并不保证是可用令牌分组。登录、同步、重新生成把账号字段或 default 当作令牌分组；创建成功后目录验证 403 又被判作过期，重复操作生成多条令牌。工具自己的分组凭据正常时也被总状态误导。

## Decision

登录与目录同步不创建通用令牌。刷新保留同账号已有通用凭据，新账号允许仅保存登录会话。通用凭据的显式修复由用户选择服务器当前可用分组，复用匹配令牌并验证后保存，不重配无关工具。正常工具继续使用自己的分组凭据；声音克隆读取同一安全凭据入口并明确提示缺少通用凭据。

所有设备令牌创建入口复用带分组校验、串行锁、完整有界分页与持久化待确认标记的获取过程；创建结果不确定时必须查询，不自动再建。HTTP 403 保持权限拒绝含义，不声称过期。失败不清除可用配置或撤销旧令牌。

## Existing decisions

[独立图像分组](../../implemented/bug-fix/2026-10-23-independent-image-group.md)部分重叠，沿用按用途分组与不自动切价规则；[模型选择分组](../../implemented/feature/2026-10-02-model-picker-groups.md)只涉及目录展示，保持不变。其余搜索命中的媒体、Accio和发布笔记不负责通用凭据生命周期。

## Alternatives considered

- 默认选择第一个可用组：用户无需操作，但可能改变计费线路，拒绝。
- 保留自动 default 创建，仅降低告警：改动小，但重复令牌和新用户失败仍存在，拒绝。
- 立刻删除通用凭据系统：更简洁，但声音克隆仍有消费者，本轮保留显式选择入口。

## Verification

本地模拟服务7项原生测试覆盖下线/空/失败分组零创建、并发重用、创建响应504后的持久标记与延迟记录恢复、完整分页、过期登录、目录403保留旧凭据并复用新令牌、验证期间切号和401/403分类。原有登录安全存储5项、声音克隆5项通过。前端53项相关回归覆盖显式分组选择、复验失败不报成功、分组刷新失败、切号丢弃、工具分组与图像入口。TypeScript和renderer构建通过。测试只使用模拟账号与本地服务，无真实令牌修改或收费请求。

创建结果不明用例在重建 AppState 后复查同一数据库，验证标记不依赖进程内存。Clippy（lib、no-default-features、warnings-as-errors）与Rust格式通过。本机未安装Bun，仓库校验入口报告缺少Bun；用Node 24直接执行同一套笔记树、格式及归档验证脚本，三项通过。未验证Windows真机或真实账户请求。

发布准备全量前端检查发现繁体中文、日语和韩语新增词条缺失，补齐后168个测试文件、1237项测试全部通过；发布版本0.1.126与最近两版公告一致。

## Consequences

减少无用途的通用令牌与不必要的工具重配，同时增加显式选择步骤。新登录允许没有通用令牌，声音克隆等附加功能需要在连接诊断选择分组；同账号刷新保留已有通用凭据。未确知分组列表时不使用缓存或账号标签替代权限事实。

无法确认的创建会保守阻止重建，需要核对服务端记录；若记录后来可见会自动复用。未提供“强制重建”绕过按钮，不在客户端自动删除历史重复令牌。分页上限为100页，超过范围停止创建。服务端尚未提供令牌创建幂等键，保护针对同一客户端账号/分组/设备名称，不能保证跨设备同时创建唯一。Windows真机验证与正式发布不由本机单测替代。

后续变化：[账号统一令牌](../../implemented/architecture/2026-11-08-account-shared-token.md)替代新配置按分组分配凭据的行为。目录筛选仍保留，新请求路由由平台令牌决定，自动路由不猜测计费组；既有配置和历史任务维持原凭据。
