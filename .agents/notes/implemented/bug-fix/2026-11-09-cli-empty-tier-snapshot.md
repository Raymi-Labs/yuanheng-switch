# Agent Note: 空能力快照不得阻止启动实时核对

Status: implemented

## Problem

生产客户端显示Fast但终端供应商的yuanhengServiceTiers.models为空。launch_tool在实时查询之前调用scope.check，空记录提前拒绝，用户无法通过重新检测页面修复。批量目录查询失败可产生空快照，不能把它当作当前模型明确无权限。

## Decision

复用配置切换锁和现有本人能力接口。启动先核对账号、托管供应商、分组、当前模型身份（不要求旧能力），仅查询当前模型，再复核配置与账号未变，将最新能力写入共享数据库和CLI模型目录，最后通过原有守卫生成一次性票据。Core继续每次从共享数据库读取，不另设授权缓存。不再为每次付费启动强制重新配置全部模型。

## Alternatives considered

- 删除守卫：会放行未授权档位，拒绝。
- 页面查询直接视为授权：有迟到和过期窗口，拒绝。
- 启动按当前模型实时核对并同步：修复空快照且保留权限边界，采用。

## Verification

原始空快照回归先稳定返回与用户一致的“当前账号、模型或分组不支持所选速度档位”，修复后通过。5项启动模块测试覆盖空记录、超时、撤销能力、查询期间账号/组/模型/配置变化、无关模型及凭据保留；完整配置函数测试确认CLI目录含Fast、Desktop Live文件字节不变、文件写入失败阻止启动。Core路由读取刷新后的数据库记录，经真实HTTP桩验证ultrafast完整出站，503仍只发一次。官方0.167.0真实TUI使用空快照、loopback能力HTTP查询、更新目录及桥接，业务请求携带ultrafast；独立标题请求不算重试。Codex相关568通过/3忽略，原生opt-in另跑通过；前端69项通过、类型、格式和Clippy通过。测试隔离账号/目录/HTTP，无真实收费模型。

## Consequences

配置落盘失败必须阻止启动；不能恢复覆盖并发的新配置。实时能力只保证查询时可用，上游实际可用性及扣费仍由服务端再次校验。CLI旧版协议差异与此问题独立，不通过删档位保护来兼容。

批量目录查询仍用于显式模型配置；付费启动不再强制重跑这一步。只修复当前模型的能力，保留相同账号分组的其他模型记录；明确不支持清除当前模型旧授权，不成功启动。目录写入失败时DB保留已确认的最新能力，但不发启动票据，下次启动仍重新查询。未改用户实际配置、线上渠道或已发布安装包，发布需走后续正式流程。
