# Agent Note: 内置图片Skill分组与实际凭据一致

Status: implemented

## Problem

图片Skill虽然保存独立图片分组，配置时仍调用账号统一令牌入口，实际可能按聊天组路由并产生非预期费用。用户撤回本轮所有通用路由方案，只授权修图片/视频Skill分组。当前仓库内置Skill只支持图片生成与编辑，视频由创作页处理；本轮不新增视频协议、不改创作页或服务端。

## Decision

复用每工具独立图像连接、系统凭据库、Core内存同步和现有图片分组选择器。安装/更新或启用Skill时采用用户已有图片组，尚无选择时默认“生图和视频”；组不存在或无图片模型则提示选择，不借聊天凭据。为同账号同图片组查找/创建专用普通API key，校验group、单组范围、关闭跨组回退及令牌可用性，不覆盖平台配置。ID和创建待确认标记可持久化；不确定、删除、停用或重复名称时不补建。后续福利补充将凭据列表改为图片模块局部有界读取，聊天统一令牌入口保持不变。

旧连接增加可兼容读取的凭据策略版本：旧记录仍显示其图片组，但不能被当作已验证的专用凭据；用户明确更新后换新连接。旧记录不阻断已更新工具的Core快照。Skill描述运行时必须使用独立图片路由；未配置时仅显示选择/连接状态。Codex原生图片和自定义API Key不是本次Skill范围，不更改其调用逻辑。

## Existing decisions

[独立图片分组](../../implemented/bug-fix/2026-10-23-independent-image-group.md)部分重叠，沿用连接绑定和单次请求，但取消Skill的自动聊天凭据回退；[统一令牌](../../implemented/architecture/2026-11-08-account-shared-token.md)仅图片Skill凭据例外，聊天、创作页、通用功能与自动路由保持原样。上一轮请求级协议的两端未提交修改已按用户要求全部撤回。

## Alternatives considered

- 仅在脚本写默认组名：不改变鉴权凭据，服务端仍按统一令牌路由，不能修复费用来源。
- 全局路由偏好协议：覆盖面大且用户明确撤回，不采用。
- 图片专用单组令牌：沿用现有服务端契约，无需部署服务端；代价是每个实际使用的图片组增加一枚客户端管理的令牌。

## Verification

本地全量Rust2781项通过、13项既有忽略；前端184文件1372项通过，另增默认组显式连接/失败不回退专项。脚本149项通过，包括多个工具独立图片路由、旧绑定拒绝、完整模型ID及单次POST；类型、renderer构建和Clippy lib -D warnings通过。图片令牌合成HTTP验证同组并发复用、不同图片组互不影响、聊天token原样、完整分页、重复/停用/删除/多组/回退/未知创建拒绝及错误账号保护。旧图片记录不进入Core快照、有效其他连接继续工作；默认组仅在无已有选择时使用。独立规范与需求审查未发现代码阻断项，指出能力图旧说明已修正。未修改真实令牌、调用模型或启动虚拟机。

收尾追加平台手动同名替换凭据的采用和响应途中切换账号的回归，图片令牌6项专项通过；最新图片组件19项、类型和Clippy复查通过。真实Chromium配合合成hook验证900/430宽度默认组按钮及无横向溢出，未读取账号资料或发外部请求；删除不再适用的“前往工具管理”跳转，直接在图片选择器完成连接。以上浏览器验证不替代原生系统凭据库或真实生图验收。

## Consequences

默认组的可用范围由[福利模型补充](../feature/2026-11-13-image-welfare-model-fallback.md)扩展：每枚凭据仍单组且routing_config为空，Core在提交前按模型目录选择主组或福利组。其他组和聊天隔离决定保持。

不把本地连接标记当作远端配置永远不变的保证；用户在平台手工修改专用令牌后，应重新校验，客户端不自动把它改回。跨设备同时初次创建无服务端幂等键，检测到同名重复会报错。当前内置Skill没有视频接口，本次不宣称修复尚不存在的视频Skill或宿主另行安装的脚本。
