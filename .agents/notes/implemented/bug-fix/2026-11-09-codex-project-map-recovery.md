# Agent Note: Codex 登录切换后的本地项目映射恢复

Status: implemented

## Problem

现场 SQLite 中的项目仍存在，但应用项目接口和全局活动映射只返回一个项目。进一步只读核对发现 `electron-account-renderer-state-v1.inactive` 完整保留了原本地项目及会话归属。问题与登录切换使用另一套界面状态相符，不能将原映射直接判作已删除，也不能仅凭配置路由证明原生登录状态。

## Existing capabilities and impact

[Codex 项目适配器](../../../../src-tauri/src/session_sync/projects/codex_source.rs)读取 SQLite 用于 DSH 同步，不能恢复账号隔离的原始项目 ID；其行为保留。扩展[工具卡](../../../../src/components/desktop/FocusToolCard.tsx)与 Tauri session_sync 命令，在官方和中转模式都提供入口。[登录指引](../../implemented/bug-fix/2026-11-09-codex-account-login-guidance.md)保持认证边界，但本地项目恢复不再仅建议重新登录。[跨客户端同步](../../proposed/feature/2026-11-03-local-session-sync.md)不负责本地账号状态，两个流程不混用。

## Decision

只读预览唯一历史登录的本地项目及确切会话归属，显式确认后合并到当前活动列表。保留项目 ID、名称、根目录与原 core ID，既有当前项目、归属、未分配选择优先，不根据 cwd 猜测；同目录不同 ID 保留为独立项目。只复制本地项目字段，不迁移账号 atoms、认证、云端项目、历史账号容器或会话正文，不改 SQLite。多个历史来源、坏格式或并发变化时拒绝写入。

客户端或 CLI 运行时允许预览但拒绝落盘；使用内容指纹验证预览仍有效，写入前复查进程和原文。串行命令、私有备份、同步临时文件与原子替换保护现有数据；备份不自动删除。不会在模式切换后静默恢复，否则用户主动移除的项目也可能被加回。

## Alternatives considered

- **从 SQLite 按 cwd 重建** — 能覆盖无历史快照场景，但丢失原界面 ID、手动归属与账号范围，且数据库有同目录重复项目，故采用完整历史映射。
- **整体恢复历史账号状态** — 可同时恢复界面偏好，但会覆盖当前账号数据与登录体验，本功能只合并本地项目字段。
- **运行时直接写入或自动恢复** — 无需退出，但可能被内存状态覆盖，也可能恢复用户主动移除的数据，采用显式预览及离线写入。

## Verification

前端全量 178 文件 / 1325 项通过；完整 Rust 测试通过，恢复模块和离线工具共用同一实现。类型、格式、renderer 构建、版本公告一致性及仓库 CI 所用 Clippy 命令通过。额外 `--all-targets` Clippy 被其他模块既有测试告警阻塞，未作为通过报告。新增回归覆盖预览无写入、运行与晚启动阻止、指纹变化拒绝、备份原文、幂等、同目录不同 ID 保留、原归属与未分配选择优先、远程归属跳过、历史账号容器不变及来源歧义拒绝。前端验证检查/确认分离、指纹提交、阻止提示与失败后清除预览。

本机使用同一代码只读预览，返回 33 个可恢复项目和 605 条可补充归属；应用仍运行时正确拒绝写入。真实宿主侧栏恢复需退出客户端再执行，未把预览或隔离测试当作本机修复成功。

## Consequences

内部格式不是稳定公开 API，仅对观察到的结构提供恢复，未知状态拒绝。进程检测与文件复验无法消除用户在最后一刻启动应用的竞态，操作期间应保持退出。原账号恢复登录通常也可能恢复原界面，但本功能不替用户登录。同目录不同 ID 保留为两个独立项目，避免把旧聊天指向新空项目。没有历史账号快照时不支持从 SQLite 强行补造；Windows/macOS 原生客户端重启验收仍需分别执行。
