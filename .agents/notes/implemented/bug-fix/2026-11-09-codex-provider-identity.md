# Agent Note: Codex 会话提供商身份稳定性

Status: implemented

## Problem

Codex 原生 app-server 对历史会话 provider ID 与当前配置进行严格比较，同名且定义相同的别名仍返回 modelProviderMismatch。原生界面只显示 name，因此两个 YuanHeng 看起来没有区别。既有离线恢复脚本在当前原生引擎上复现错误，旧别名投影只能避免缺少定义，无法保证恢复成功。

## Existing capabilities and impact

复用 codex_history_routes 的拥有权判定、配置投影和原生离线恢复测试。模式切换、重配及 Core 刷新继续走现有入口。官方路由检测与清理需根据选中定义判断，不能把 ID 当作模式。既有通用历史迁移固定到 custom，可能撞上用户自己的 custom，不用于本次修复。

## Decision

托管路由切换保留旧配置中已验证拥有的活动 ID，保留外部同名 provider。官方检测依赖托管定义的 OpenAI/本地路由特征。提供显式离线修复工具，把确认归属且与当前定义一致的别名历史统一到当前 ID；备份、退出检查、失败回滚，保持正文及其他 provider 不变。

## Alternatives considered

- 只补别名定义：不改历史，原生引擎实测仍拒绝恢复。
- 把所有同名 provider 自动统一：可以减少阻断，但名称不证明端点或凭据等价，本机 custom 就是外部直连定义，不可据名称改写。
- 修改原生应用或运行中批改数据库：能绕开提示，但破坏签名或与活跃 writer 竞争，不采用。

## Verification

本机原生引擎隔离复现 modelProviderMismatch；修复后三种旧 ID 在官方、中转与原生清理模式共九次恢复通过，未启动模型轮次。650 项 Codex Rust 测试通过、2 项忽略；维护工具六项测试覆盖索引与文件同步、备份、幂等、退出检查、异常回滚、外部路由保留、缺失报告及 zstd。

## Consequences

已加载的原生会话需退出重开。离线历史修复不能在当前宿主聊天仍运行时应用；未知与用户自定义 provider 仍需要用户自己选择原提供商。

维护工具仅支持 macOS/Linux，要求 Node.js 24+（高于仓库常规 Node 下限，仅用于离线维护）。缺失索引对应文件、歧义记录及超过解码资源上限的文件报告跳过。本机仅预览，206 条可处理记录未实际改写。中断清单阻止重复执行，进程强杀或磁盘故障需维护者停机核对备份恢复。

独立工作区使用 CI 的 Node 20 完整通过 178 个前端测试文件、1328 项测试；类型、格式、Vite 构建、Clippy、版本公告及决策笔记校验通过。原共享工作区的其他任务变化不纳入提交。

合入 CLI 速度修复主线后版本顺延到 0.2.13；Node 20 前端全量 179 文件/1336 项通过，Node 24 维护工具 6 项通过。独立工作区补齐被忽略的 Core 旁车文件后复验后端。

随后主线项目恢复更新占用 0.2.13，本修复最终顺延为 0.2.14；后端复验 652 项通过、3 项忽略。

最终主线前端 180 文件/1339 项中首次出现一个 DSH shell 超时，单独重跑该文件 7 项全部通过；其余 1338 项首次通过。
