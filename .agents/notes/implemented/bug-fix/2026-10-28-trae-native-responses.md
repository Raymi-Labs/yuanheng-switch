# Agent Note: TRAE 国内版原生 Responses 协议兼容

Status: implemented

## Problem

国内版已保存的Chat Completions条目在实际Astra任务中返回none思考强度不支持。编辑高级配置后的连通检查通过，但目录和任务保留旧gpt6系列。元衡向导又把国内版Responses隐藏，依据早先不完整的入口观察限制了实际官方能力。

## Decision

当前官方3.4.9/build2.3.97430的原生菜单明确列出OpenAI Chat Completions、OpenAI Responses API及Anthropic Messages。保留原Chat Completions条目，使用相同gpt-6-astra、鹈鹕王Key和元衡域名，通过官方UI新增独立Responses条目。正式请求路径为`/v1/responses`，模型系列默认；不再要求在旧条目反复修改未生效的高级设置。

元衡复用现有辅助向导，纠正国内版协议列表，切换发行版保留两版都支持的已选协议。仅当国内版明确选择仍在有效目录中的gpt-6-astra时，显示经原生验证的说明与“使用 Responses 配置”按钮；点击只更新填写说明，不请求模型、不写官方配置。其他模型不强制协议或思考值，不迁移Key/分组、不改官方程序或私有数据库。辅助配置不等同于自动导入；原有一键自动配置缺口继续保留。

## Alternatives considered

- 删除并重建原Chat Completions条目：有机会避开旧参数保留，但会丢失对照且不能保证任务侧不再注入none；先保留原条目，使用独立官方协议对照。
- 在元衡Core新增TRAE专用兼容代理：可以按能力修正参数，但需新增凭据、路由、取消与状态管理；官方协议若已可用，则没有必要承担额外维护成本。原生路线失败再评估。
- 修改生产渠道全局思考参数或官方安装包：前者可能影响其他Agent并扩大上线范围，后者破坏官方签名/更新；不采用。

## Consequences

用户可以通过官方Responses入口使用已实测的Astra文件能力，无需删除旧模型、改官方签名或新增常驻转发层。代价是仍需原生登录和填写一次表单；不能称为完整自动配置。仅验证Apple Silicon Mac、当前国内版与鹈鹕王/Astra组合，其他模型、组和系统仍须各自验证。未知旧版需先更新并查看实际协议菜单。

官方高级设置编辑未生效的问题仍存在，此方案避开出错的旧Chat Completions路径，不宣称修好了TRAE内部所有参数保存。用户已授权同一元衡工具Key进入TRAE官方表单，本轮没有读取官方登录凭据，没有把Key写入测试文件或公开日志。
