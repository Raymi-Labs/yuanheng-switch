# Agent Note: 创作分组按实际媒体目录过滤

Status: implemented

## Problem

媒体页面直接列出所有授权分组，纯文本组也出现，让用户逐个试错。现有模型目录已经通过profile判定客户端适配的图片/视频模型，但分组列表未复用此口径。

## Decision

账号授权分组逐组查询模型目录，仅保留至少一个已适配图片或视频型号的组；保留只有视频或只有图片的组，不依赖名称。沿用既有profile，不新增模型限制。最多四个并发、单请求及整批有时限，失败分组不作为空组；返回未能验证的分组数量，界面给出简短失败提示与已有刷新入口。成功组保持可用，全失败报错。保存选择同样验证非空媒体目录。

失效偏好不自动回退，隐藏无媒体分组的旧选择并要求重选；保留草稿与历史任务。下拉只显示组名，移除重复/冗长描述。继续保留伙伴共享令牌路由，不修改计费与历史凭据。

## Alternatives considered

按名称含“图片/生图/视频”过滤会漏掉综合组或改名组，且错误保留名为媒体的文本组，不采用。

全部组照常显示再让用户选择后看到空态是当前缺陷，不采用。逐组全失败才拒绝，局部失败保留成功组并报告未验证数量，避免一个不可用组阻塞所有创作。

## Verification

模拟HTTP验证文本/空目录组消失，图片/视频组保留且名称不影响判断；局部失败、全失败、业务失败、权限撤销、过期账号拒绝；不可见旧偏好不回退。前端失败提示与组名渲染、原创作流程回归通过。检查结束遗留工作进程为零。

## Consequences

增加分组模型目录只读请求，有界并发与时限控制；未知/未适配型号无法在此客户端创作，不应误宣称平台组完全无媒体能力。过滤结果不替代提交时实时权限校验。只有本地修复，不推送发布。
