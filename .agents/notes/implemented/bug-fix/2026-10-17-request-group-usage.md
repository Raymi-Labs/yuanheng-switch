# Agent Note: 请求分组快照与桌面缓存计价

Status: implemented

## Problem

请求日志把独立的全局报价选择显示为请求分组，平台使用优质分组时仍显示企业专属。chatgpt-desktop 的 Responses 输入包含缓存，但本地被标为 fresh 并重复计入缓存，截图中的 0.25684 与 2.31124 可由相同原始用量复现。

## Existing capabilities and impact

复用 RequestContext 中故障转移后的 Provider、元衡托管配置的 group 信息、UsageLogger、platform_pricing 和 PlatformQuote。现有报价选择保留为报价目录的比较工具，请求日志、详情和统计金额统一使用逐请求快照。检索无已有报价归属笔记；[Codex 配置恢复](../../implemented/bug-fix/2026-10-14-codex-surface-mode-repair.md)部分重叠，继续保留 CLI/Desktop 独立分组，不改配置时机。

## Decision

发送时使用的 Provider 快照携带令牌分组，流式和非流式完成后随请求落库。UI 标为请求分组，不能声称平台最终结算分组；服务端外部改令牌、自动路由或跨组回退仍需平台账单确认。历史、非托管及官方会话没有证据则未知，不能按当前配置反填。金额按请求组估算，不再使用全局组；自动组不猜测结算倍率。数据库新增 nullable request_group，并只修正既有 chatgpt-desktop proxy 明细输入语义；保留旧 USD 成本及已经归档的 rollup，不伪造历史金额。前后端、聚合与本地计算补齐桌面 OpenAI 缓存语义。

## Alternatives considered

- 读取当前工具分组：无需迁移，但切组后历史会变化，流式请求完成时还会读到新配置，故记录请求快照。
- 只把企业专属文案改成估算：仍无法反映用户请求，且统计金额继续跨组错误；报价目录可保留比较功能，日志不能套用。
- 直接读取平台账单：可确定最终扣费，但现有本地日志没有平台逐笔关联契约，本轮不增加跨项目 API 或按时间猜配。

## Verification

完整 Rust 测试通过 2501 项，3 项既有忽略，Clippy -D warnings 通过。新增真实请求上下文回归覆盖 JSON 与 SSE：在请求选择 Provider 后、流完成前切换数据库分组，仍保存原始优质分组；非托管及非元衡 Provider 不取得分组。混合企业/优质/未知/自动请求的明细与汇总测试证明全局目录选择不改变金额；截图样本按优质倍率得到 0.115578，缓存只扣一次。迁移可重复执行，仅修正桌面 proxy 语义，不赋值历史分组、不更改 USD 成本。

前端最终完整 145 文件、927 项测试通过，包含自动组分支。TypeScript、全量格式、renderer 构建、版本公告及 29 篇笔记校验均通过。实际应用壳使用本地模拟 Tauri 数据在浏览器验证：优质、企业、未知三行分别显示；刷新保留展示；全局选组不出现在用量页；报价同步失败保留请求分组。浅色 1440×1000、深色 1000×720 和原生最小 900×600 截图已检查，表格保持水平滚动，金额不折行。390px 小于原生最小宽度，既有桌面壳不适配手机，未扩大为布局重构。此验收不调用真实付费模型、不代表平台逐笔账单核对。临时预览与浏览器在验收后删除、关闭。

## Consequences

历史未知记录不再产生全局参考估算，统计会显示未覆盖。记录的是元衡托管令牌的请求分组，服务端外部修改、自动路由和跨组回退仍需平台账单确定最终结算；不能把客户端配置快照称为已确认扣费。升级不会追溯猜造分组，也不覆盖真实平台账单。旧归档 rollup 没有原始上下文，保留旧值并不补造报价。
