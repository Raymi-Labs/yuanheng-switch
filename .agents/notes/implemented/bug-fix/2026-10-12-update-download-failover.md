# Agent Note: 跨地区更新下载择源与续传

Status: implemented

## Problem

国内与海外用户都反馈客户端下载和升级缓慢。当前更新清单有官方镜像和 GitHub 两个端点，但获取清单成功后只下载其中一个包，慢速或断流不会切源。2026-10-12 本机带代理完整下载同一个约 23 MB DMG，镜像耗时 31.4 秒、GitHub 5.0 秒；此结果不是国内三网测速。公开镜像包同时返回 immutable 与 no-store，源站 Nginx 通用 location 已确认追加禁止缓存头。

## Existing capabilities and impact

复用 [更新命令](../../../../src-tauri/src/commands/settings.rs)、[代理策略](../../../../src-tauri/src/services/updater_proxy.rs)、[更新状态](../../../../src/contexts/UpdateContext.tsx)、Tauri 安装器及既有公钥/签名。所有登录前后更新入口共享本命令。搜索活跃笔记：登录前更新与顶部更新入口部分重叠，仍保留其 UI/认证边界；出站连接稳定性笔记不拥有独立更新器下载策略。发布与镜像脚本继续拥有三平台完整性与先包后清单顺序。

## Decision

仅对当前项目的固定版本官方包构造镜像/GitHub 两个同版本地址，小量并发试下载选先完成的源，取消另一探测。单次更新内保留内存字节，通过 Range 在断流、停滞或持续低速切源时续传；忽略 Range 的服务器返回 200 时清空旧字节重新下载。校验 Content-Range、总长和大小上限，限制尝试次数、停滞与整体时间。完整包必须通过与 Tauri 相同 minisign-verify 库及同一公钥/签名验证后才安装；签名失败清空混合数据后尝试另一源。未知发布地址沿用 Tauri 单源下载，不猜测其他源。不改变用户代理规则。

进度携带明确下载/安装阶段，签名验证前不因字节满额进入安装，重下载进度可回退。安装命令后端互斥。不持久化部分包，退出程序后重新下载；此范围避免引入磁盘缓存、生命周期和清理协议。源站下载专用 location 经用户单独授权上线；新增 CDN/费用不由客户端发版授权。

## Alternatives considered

- 永久优先 GitHub：本机快，但无法代表国内用户，因此按实际试下载决定。
- 两个源同时全量下载：最快完成者获胜，但每次升级可能加倍流量；只探测小块，再在异常时切换。
- 持久化断点文件或增量更新：能减少退出后的重下载或更新体积，但引入缓存失效、磁盘拥有权或差分包构建协议；20 MB 级安装包先解决当前单次下载链路。
- 只修缓存/CDN：首次下载受益，但新节点未就绪时及不同地区故障仍缺少客户端恢复能力；分别验收。

## Verification

11 项 Rust 下载/签名回归通过，本机完整 Rust 测试 2487 项通过（另 3 项忽略），CI 同款 Clippy、格式检查通过。扩展的 `--all-targets` Clippy 命中两处原有测试 lint（core_diagnostics 的 cloned_ref_to_slice_refs、secure_storage 的 items_after_test_module），不修改无关测试。前端全量 901 项通过，随后补齐原生字符串错误展示并通过 21 项相关回归、类型检查及 renderer 构建。浏览器真实 App 壳 + 模拟 IPC 验收深浅色、900×600、100% 仍下载、切源清零、显式安装、失败重试；模拟不代替原生安装。

手动 `live_signed_release_download` 使用生产相同下载核心与公钥，真实获取 v0.1.74 的 22,982,097 字节包，7.64 秒完成下载/签名校验，没有安装。此单机代理网络结果不作为全国提速承诺。

源站候选完整配置通过 `nginx -t`，经用户明确“现在应用，并验证公网下载”授权，备份后平滑重载，Nginx active。公网安装包 HEAD/206 保留唯一长期缓存头，404 为 no-store，清单/API 状态正常且继续禁止缓存。随后公网整包下载仍慢（60 秒约 1.8 MB）；源站应用完整文件 0.139 秒、源站 Nginx 0.180 秒，而源站绕公网入口中转下载仅约 28 KB/s。缓存头修复已上线，入口中转/链路性能仍需独立排查，不能宣称全网下载已恢复。

使用用户提供的腾讯云 SSH 密钥继续只读复核：实时 DNS 公网入口与腾讯云硅谷是不同服务器。当前入口的约 33 KB/s 低吞吐由源站、腾讯云两处复现；腾讯云回源完整 23 MB 包约 1.6 秒，源站经腾讯云入口取完整包约 6.66 秒，TLS、Range、清单、API 与 404 语义正常。但 Mac 到腾讯云无显式 HTTP 代理与使用现有 HTTP 代理两种请求均约 17–18 KB/s，GitHub 同轮约 0.78 MB/s 且未在 25 秒内完成整包。服务器之间快不能推出国内用户快；没有切换 DNS 或修改腾讯云配置。采样路径、长度、超时及系统隧道限制见[下载分发验收](../../../../docs/guides/desktop-download-delivery.md#入口与用户侧路径复核)。

## Consequences

2026-10-13 用户另行授权 R2 实测后，专用 APAC 桶与 `download.meta-api.vip` 已建立，仅承载公开 v0.1.76 ARM 更新包。8 次整包下载及四轮精确 Range 字节校验通过；Mac 现有代理/TUN 网络缓存命中 3.02–4.83 秒，原入口单独复测仍约 61.7 KB/s。两个海外服务器 R2 整包 0.66–3.25 秒；GitHub 部分采样更快，因此保留择源理由。新域名是测试入口，正式清单、客户端地址识别、发布流水线尚未接入；没有国内直连数据。见[R2 下载实测](../../../../docs/guides/desktop-download-delivery.md#2026-10-13-r2-下载实测)。这补充网络验证事实，不把 CDN 可用等同于正式迁移完成。

探测额外消耗至多每源 256 KiB；HTTP 忽略 Range 可能多传一些在途字节。不同源数据不一致会使最后签名失败并重新下载，不允许安装混合内容。小块择源不保证整段始终最快。只在本次更新操作内续传，手动重试或退出应用后重新下载。不改首次安装网页，缓存修复不会自动部署 CDN。下载功能提交与另一聊天的 Apple 发布流程修复分开，版本号/公告与正式发布由该聊天统一完成；提交与本地验收不等于三平台正式版已发布。
