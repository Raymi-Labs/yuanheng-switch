# Agent Note: DSH 托管 Claude 的空闲等待与有界重试

Status: implemented

## Problem

DSH 的 pi-ai 默认在等待下一条模型输出事件超过五分钟时取消请求。复杂 Claude 任务可能尚未结束，用户却只得到空闲超时；保留默认五次重试并延长单次等待会把一次失败拖至近一小时。目标是给复杂任务更多等待空间，同时控制重复请求、保持停止有效，并让已有配置获得同一策略。

## Decision

元衡 DSH 的事务配置入口只给托管 `yuanheng-messages` 路由写入 `streamIdleTimeoutMs: 600000` 和 normal 模式、`maxRetries: 1`。其他路由和用户自有供应商不写新默认值，SDK 的错误分类与退避仍由固定版本 DSH 负责。停止、凭据、模型目录、恢复和写入锁沿用已有流程。

旧配置的完整性与策略新旧分别判断：可信旧配置仍可读取凭据和恢复；状态检查两个托管 profile 的 Claude 策略，缺失或不匹配时提示需要重新应用。重新配置仍核对拥有权 hash，外部改过的托管块不强行迁移。配置后刷新或重启 DSH；已运行的请求不追加等待时间。不迁移自定义 profile、远程 Web 或用户手工供应商。

## Existing capabilities and note audit

入口为当前工具卡与工具管理，经 `configure_yuanheng_tool` 到 `yuanheng/dsh.rs::configure`，共同写桌面与 Web patch，使用凭据复用、原子文件和拥有权记录。DSH 0.2.0-rc.2 已支持按路由设置空闲超时和重试策略，无需改 SDK 或 newapi。当前能力地图及配置入口均已核对。

[DSH 安装与启动](2026-10-11-dsh-install-launch.md)部分相关，继续拥有安装和进程监督；本笔记只记录模型请求策略。安装取消、网络连接池、窗口更新等活跃笔记不涉及此策略，不修改其决定。

## Alternatives considered

- 修改 SDK 全局默认：覆盖面直接，但会同时改变其他供应商和用户自有 DSH；已有路由字段足以完成目标。
- 仅修改服务器超时：无需客户端更新，但客户端自己的五分钟 watchdog 仍会取消；不能替代本次修改。
- 仅延长到十分钟并保留五次重试：短暂故障恢复机会较多，但初始请求加五次重试可能累计近一小时并重复产生用量。
- 取消空闲上限或无限重试：不会因固定阈值提前结束，但无法控制真正停滞请求的等待和资源占用。

## Consequences

真正停滞的单次请求最多多等五分钟，连接和并发占用也会延长；减少自动重试会减少部分瞬时故障的恢复机会。等待时间不是计费公式，但模型额外处理可能增加 Tokens。更短的服务器、代理或上游时限仍可能先触发，客户端调整不能证明渠道恢复或 Windows 真机正常。源码合并不代表安装包已发布或用户配置已更新。
