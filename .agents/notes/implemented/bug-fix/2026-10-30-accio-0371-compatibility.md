# Agent Note: Accio 0.37.1 官方升级兼容

Status: implemented

## Problem

v0.1.117发布时官方更新源及用户本机已经是Accio 0.37.1，但产品只接受0.34.5/0.35.3，导致正常官方新安装在配置前被拒绝。错误未包含实际检测版本，排查又要求用户手动找版本号。

## Decision

原生验证发现0.37.1 read有互斥的json_path/json_paths可选参数，真实Astra连续返回两者（后者空数组），官方拒绝执行。Accio转Responses工具声明显式strict:false，保留源工具可选语义，参数schema原样透传，不在响应端随意删除模型输出参数；改动仅位于Accio适配器。官方文档页面本轮访问403，不以未获取页面作为验证依据；新Core原生任务实测确认改善。共享转换器与其他Agent不改。

复用现有签名、版本预检和Core受控启动链，对0.37.1官方worker做固定摘要的目录/模型协议回归，并验证配置/启动边界后扩展精确版本列表。保留未知版本拒绝及Windows不支持边界。错误包含已校验的实际版本。官方程序源码只在本地读取，不提交厂商包或用户数据。无网络的协议测试先行，不启动宿主个人工作区。

## Existing note review

- [已验证入口](../../implemented/feature/2026-10-21-accio-verified-desktop-entry.md)继续持有签名及受控启动规则，本篇补充新版本和漏检官方更新源的验证缺口。
- [Core升级](../../implemented/bug-fix/2026-10-30-accio-core-upgrade-before-launch.md)保持现有升级保护，不为适配新版本另建启动器。

## Alternatives considered

- 直接放行所有新版本：用户立即不再被拦，但未知协议变更会进入真实请求，无法证明兼容，拒绝。
- 要求用户退回0.35.3：不需改代码，但与官方新安装和自动更新冲突，不能解决正常用户路径。
- 固定新版本协议证据后扩展现有规则：范围最小，可复查，未来官方再升级仍需重新验证。

## Verification scope

- 官方Bundle ID/Team ID验证，更新源版本与样本一致。
- 新旧官方worker的目录、工具流、取消、权限边界回归通过；不以更改期望值掩盖协议差异。
- 0.37.1受控配置/启动可用，未知版本、假签名及已有活跃会话保护不变。
- 测试结果与遗留进程为零同时满足；实际模型或原生未验证项单独记录。

## Consequences

新版目录增加隐藏模型侧表和当前区域的兼容缓存保存，离线夹具必须保留其逻辑或明确隔离的磁盘依赖。官方应用遥测/设备信息仍有边界，原生测试优先沿用专用QA环境。

## Verification

官方更新源beta-mac.yml与本机签名包均为0.37.1。官方worker SHA256为23f247a2135233570b73f9dd8c11b958bcaba934bcedf49f32c48316858a3980；仅从官方app.asar提取程序代码，不读取个人运行数据。原有离线脚本新增固定哈希及局部符号映射，15项协议检查通过；0.35.3同15项复验通过。原版schema、目录加载、SDK模型构造、protobuf、SSE分片、工具参数、错误与取消逻辑在隔离上下文执行；隐藏模型侧表保留WeakMap，磁盘兼容缓存决策单独stub，不能声称验证磁盘迁移。计时器0、外部请求0。首次新SDK重命名误命中Object原型constructor，改为Object.hasOwn后通过；修正环境表符号映射后测试通过，未改断言期望规避失败。

本地产品精确接受0.37.1，未知版本继续拒绝；错误带实际版本。Accio相关Rust60项及Core构建通过，包含认证、路径、假签名、旧capability、重复启动和其他Agent协议隔离。官方0.37.1保留签名复制到已有专用QA虚拟机独立目录，通过修复后真实Core管理接口受控启动返回200，原生主界面出现、原登录仍在；未替换QA原Accio安装。新debug Core触发macOS本地网络授权弹窗，未代用户批准，未发送付费模型请求。原生模型/文件实测暂待授权，不把启动成功等同完整使用通过，不发布新包。

收尾：活跃请求0后关闭测试Accio与Core，原Core首次恢复未成功，确认无运行Core后单次重试恢复成功；随后停止，验证业务配置不变、route inactive、测试App/Core/GUI进程0，专用VM正常关机。未关闭系统安全检查或代点权限。

用户授权后复验：原生0.37.1模型调用通过，但首次文件任务因json_path与空json_paths同时出现而5次工具失败，输出文件不存在。新增非严格工具声明后61项Accio回归通过，包括flat/grouped工具可选schema原样保留、三协议转发及隔离。新Core SHA256为3059a8a46d92463e5e5674146079d548e712dc6bb05810a3acc8703749797a8c，管理启动HTTP200；使用同一合成文件夹及新会话，Astra完成read→write→read→edit→read，实际文件随机marker一致、total=83、verified=true，input/guard未变，6次请求全部200且正输出。写入和修改逐次通过原生审批，未放宽全局权限。最终UI回复与磁盘内容一致；离线取消已验收，原生停止、其他模型、Intel及Windows仍不由本轮推断。
