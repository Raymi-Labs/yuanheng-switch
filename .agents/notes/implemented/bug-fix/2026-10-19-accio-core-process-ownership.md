# Agent Note: Accio 子进程由 Core 持有并验证访问资格

Status: implemented

## Problem

Accio 的访问能力地址只应对当前受控启动有效。[主模型桥接提案](../../proposed/feature/2026-10-18-accio-primary-model-bridge.md)中的 GUI child.wait 清理能处理普通退出，无法处理 GUI 先退出或崩溃。独立 Core 会继续接受磁盘 active 标记，甚至重启后恢复孤立能力地址。让用户保持窗口开启不符合桌面与 Core 分离的现有行为。

## Decision

GUI 只发现应用路径，经已有 Core 管理凭据请求受控启动。Core 再核验固定 Bundle ID、Team ID、签名与已验证版本，串行启动并直接持有 Child。访问端点同时要求有效配置、相同能力令牌，以及该 Core 内存中仍存活的直属子进程。使用真实 Child 的 try_wait，不根据可复用 PID 或系统时钟推断身份。

Core 周期清理和每次请求检查共同保证子进程退出后撤销；GUI 退出不影响该检查。新 Core 不采纳上次进程的运行标记，要求从元衡再次启动；不自动停止/接管已运行官方进程，不给官方 App 修改系统环境。管理调用限定 loopback、Host、无 Origin、管理 Bearer 和有界 JSON；不在网络错误后重发启动。配置变动期间启动只接受同一配置快照，异步校验后重新核对，避免账号切换或断开后的迟到启动。

macOS 实验 Core 先持有配置目录的文件排他锁，再初始化数据库；旧 active 清理仅在成功绑定端口后、接收 HTTP 前执行。第二实例锁失败或绑定失败均不得改动现有 capability。锁文件不删除，句柄有 CLOEXEC，OS 在崩溃时释放；Core 停止时内存状态禁止验证中迟到的启动。配置版本通过现有 canonical JSON 排序再哈希，避免嵌套 Map 序列化顺序制造随机冲突。

## Existing decisions

- 主模型桥接提案部分重叠：本篇接管其中进程生命周期/访问授权的选择，协议、分组隔离、未知版本拒绝仍归原篇。两篇互链，不把旧清理理由删除成无法检索的历史。
- 原有 Core 独立运行与 GUI 退出保持路由的行为复用，不改变其他 Agent 的进程、配置和访问资格。
- 本轮连接器重试兼容由主模型桥接提案和兼容性报告记录；与本篇共用入口鉴权，但不共享模型/官方认证凭据。

## Alternatives considered

- GUI 定时续租：实现短，但 GUI 关闭或挂起会令仍在工作的 Accio 失效，与独立 Core 的产品目标冲突。
- 磁盘 PID 加启动时间：允许 Core 重启后尝试接管，但需跨平台进程身份、路径及 PID 复用处理，而且不能可靠获得原父进程的 Child 退出状态。当前实验阶段没有必须自动接管的需求。
- 仅 GUI 正常退出撤销：改动最小，但无法覆盖 SIGKILL，且会中断用户有意保留的 Accio 会话。
- Core 持有 Child：需要一个受限管理端点和内存状态，但复用现有服务鉴权与周期任务，无新增独立守护进程，生命周期明确。Core 重启后必须重新启动 Accio 是明确代价。

## Verification

回归覆盖孤立 active 配置、新 Core 实例、错误能力令牌、非 loopback/外部 Origin、无管理凭据均失败；只有当前直属活进程能够访问。调用方消失不撤销活着的子进程，子进程退出在下一请求或一次周期后撤销。重复启动、账号切换、断开、启动取消/失败、旧进程迟到清理不影响新配置或新能力。真实 Core 进程测试使用隔离端口和假模型凭据，无收费推理。正常退出与测试异常结束均验证无残留进程。

## Consequences

官方自行更新/非元衡重启仍不受此 Child 身份认可；不得自动信任其继承环境或接管同名进程。启动请求超时可能发生响应遗失，前端要明确提示检查状态，不能再次启动或虚报失败即没有子进程。签名检查与可执行文件打开间仍有操作系统允许的文件替换窗口，沿用签名路径边界，不把它描述为完整沙箱。

## Native evidence

实际 Mac ARM 官方 0.34.5 使用固定哈希的实验 Core、假模型 Key、已有独立官方登录态进行短时空闲测试；未发送模型提示。启动管理 HTTP 在 80ms 主动中断后仍只有一个直属 Accio 子进程，目录可用；子进程退出后旧地址 401，重启 Core 后仍 401。官方 userinfo 恢复返回 200。取消/并发/进程退出/变更账号/慢正文撤销/旧 Core 运行标记等由 Rust 回归覆盖；真实 Core 重启与重复启动检查见 `scripts/test-accio-core-lifecycle.cjs`。

共享代理回归通过，完整官方更新/新安装与非 ARM Mac 仍未验收。本轮测试以零遗留子进程、Core、监听端口与隔离链接为清理条件；正式元衡和 Core 不在清理范围。
