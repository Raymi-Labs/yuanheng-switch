# Agent Note: Codex 首次配置与旧标记恢复

Status: implemented

## Problem

只配置 Codex Desktop 时，configure_codex_surface 将选中配置复制到 CLI 命名空间，保留了 desktop 标记；先配置 CLI 同样会把 terminal 标记复制到桌面端。当前工具状态只检查自身，因此可显示已配置，账号方式切换却要求两份配置标记分别正确，导致中转用户被错误提示重新连接账号。重新配置同一工具仍保留另一份错误标记。

## Existing capabilities and impact

复用 yuanheng.rs 的配置、账号方式切换锁、文件/数据库快照回滚、两份独立模型配置及凭据检查。工具管理和工作台调用同一配置入口；方式切换的只读前置校验与实际写入必须使用相同的可恢复判断。

现有[工作台单入口笔记](../../implemented/simplification/2026-10-12-workspace-single-tool-controls.md)部分重叠，继续保留独立工具选择与原配置时机；本次修正底层数据标记。官方登录检测、历史会话保护和其他工具的配置不被替代。

## Decision

新配置及重配时按命名空间纠正元衡拥有的 terminal/desktop 标记，保留两边原有模型、分组、密钥和目录。旧版错误标记在只读检查中视为可恢复，但不冒充已应用；用户明确切换元衡时在现有事务中纠正标记并写入两份路由。不扩大到未知标记、第三方配置或缺少凭据的记录。官方模式继续要求官方登录，提示明确说明中转账号应使用元衡中转。

## Alternatives considered

- 要求用户分别配置 CLI 和 Desktop：可绕过现有缺陷，但桌面用户不应为了一个配置标记安装 CLI，且重新配置同一工具不能恢复。
- 直接取消所有标记校验：改动少，但会把未知或不完整的配置当作可用；只接受原逻辑产生的已知标记并保留凭据和拥有权检查。
- 启动时迁移数据库并写路由：升级后自动完成，但后台检测不应改变用户选定模式；在明确配置或切换时修复。

## Verification

新增实际 configure_codex_surface 回归在原代码失败于“one configured tool must allow switching”，修复后 CLI/Desktop 两个首次配置顺序均通过；测试使用临时目录、内存数据库与随机端口本地代理，不访问客户电脑或模型上游。单工具配置仍不改写另一侧路由，API key 登录材料保持原样且不被识别为官方 OAuth。

15 项 Codex 相关回归通过，覆盖双 desktop/双 terminal 旧标记恢复、只读状态不迁移、独立模型/分组/凭据完整保留、未知/无凭据/非元衡/外部端点拒绝及官方切换边界。阻塞桌面目录写入后验证标记、CLI 路由与桌面配置回滚。

全量 cargo test 通过 2493 项，3 项既有忽略；Clippy -D warnings、Rust 格式检查通过。前端 144 文件/923 项测试、类型、格式、renderer 构建与版本公告检查通过。renderer 仅有既有包体积提醒。

## Consequences

桌面用户无需为恢复中转切换额外安装 CLI。可恢复不等于已经应用，状态判定继续读取真实路由与原始标记；后台检测不改写用户配置，明确配置/切换时沿用原事务与回滚。恢复只涵盖元衡拥有的已知标记，不补造缺失凭据、不放宽官方登录条件，不覆盖其他工具或用户自定义配置。测试不代替客户 Windows 真机与真实上游推理验证。
