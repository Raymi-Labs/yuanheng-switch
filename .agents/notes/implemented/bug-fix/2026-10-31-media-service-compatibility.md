# Agent Note: 创作服务等待与图片链接兼容

Status: implemented

后续用户明确确认Omni720p已可用，[开放决定](../feature/2026-10-31-enable-omni-720p.md)替代本篇对此型号的屏蔽；其他限制不变。

用户随后要求下掉Veo，客户端继续不列出、不接受其新提交，并从“待验收开放”改为不在支持范围；没有删除旧作品或操作平台渠道。拒绝提交回归继续保留。

## Problem

上一批本地媒体实现使用60秒视频提交超时，而服务端Omni1080p已记录224秒才返回ID。Veo Lite最新验收为完成后内容下载403/502，Omni720p提交结果未确认；目录可见不应自动开放这些型号。仅接收内嵌图片漏掉合法URL结果。

## Decision

按用户要求所有视频POST请求deadline为600秒，图片300秒、查询20秒、下载90秒不变。禁用Veo Lite和未完整验收的Omni720p，历史查询保留。

图片兼容内嵌数据和受信任HTTPS结果URL。沿用共享无重放HTTP客户端及用户代理，URL限定平台、OpenAI图片存储、xAI图片和Google存储域名，拒绝IP字面量、账户信息、非443端口及跳转；不随意扩大为任意外部域名。先以5秒上限解析地址，任一非公网地址即拒绝；直接连接固定使用这些地址，代理连接由受信任的用户代理解析，TLS域名验证保留。不附带元衡Authorization/Cookie，错误不回显签名URL，校验文件头和64MB上限。

签名URL按账号和操作编号存入系统凭据库，SQLite和前端仅保留completed/hasMedia状态；预览和保存时只下载原图，删除作品同步清理URL。不会因下载失败改为重新生成。

## Existing note review

[创作入口](../../implemented/feature/2026-10-31-media-studio.md)部分被替代：图片从仅内嵌扩展到受信任URL，其他凭据/账号/任务边界保留。服务端等待和首帧验收记录是外部事实，不把本地测试当作线上完成；既有诊断改动无关。

## Alternatives considered

- 全局提高超时最简单，但会影响聊天和状态查询；只调整视频提交。
- 任意URL自动下载兼容面更大，但会开放本机网络访问与凭据泄露风险；先限制已知图片域名，未知域名明确拒绝，等待证据后扩展。
- 下载失败丢弃URL省去存储，但用户只能重新生成；用系统凭据库保存原结果地址，保持可恢复下载。

## Verification

媒体原生15项通过，实际生产请求构造器生成的5类视频POST timeout均为600秒、图片300秒；禁用型号无法通过profile/validate；URL协议、端口、域名后缀注入、内网/保留/映射IP、签名地址账户隔离、内嵌优先、下载GET无Authorization/Cookie、HTTP跳转、错误正文、超大Content-Length及非图片内容均覆盖。测试使用本机HTTP和合成凭据库，没有付费请求，也没有实际访问CDN。

共享HTTP14项回归通过，包括15秒账号期限、代理切换与连接复用、禁止重定向和隐式POST重放。前端媒体/侧边栏/翻译24项通过，新增600秒提示及原图下载失败后仅重试同一下载、不重新生成的回归。新测试清理时先卸载组件再还原URL mock，避免测试环境移除blob API后触发清理异常。

类型检查、renderer构建、Rust格式、Prettier、diff检查、GUI/Core Clippy（lib、bins、-D warnings）通过。静态检查要求简化地址过滤的布尔表达式后重新验证；未忽略规则。renderer保留既有chunk体积提醒。无需再次跑前端全量或无关原生套件；没有上线或更改用户代理配置。

## Consequences

可信域名白名单可能拒绝新的CDN，不能以静默下载任意URL消除此边界。共享代理仍由用户信任，HTTPS目标身份验证保持。600秒不能覆盖上游/CDN自己的更短超时，仍保留不重放规则；真实收费验收未因模拟测试而完成。

下载请求仅在预览/保存时发起，系统凭据库不可访问或签名URL过期时会失败并保留记录；不会为取图重新生成。下载服务可观察常规网络出口IP，但不获得元衡凭据、电脑名称、用户描述和参考图。媒体入口当前仍为本地未发布改动。
