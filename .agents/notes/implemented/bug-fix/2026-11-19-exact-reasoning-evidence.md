# Agent Note: 托管推理能力按精确证据解析

Status: implemented

## Problem

账号无人工声明时，型号前缀可把六档降为四档，也能给同名前缀的未知模型虚构档位。仅修名单不解决下一次上线。

## Decision

沿用[账号目录及工具交集](../feature/2026-11-18-platform-reasoning-profiles.md)，先取当前账号对精确型号的声明，再取公开来源的离线快照；没有证据不推断手动档位或默认，不把未知写成 `none`。选择、模型能力和工具能写入的协议字段是三件事。托管 Codex 目录的“无默认”可以写入并读回，不由其他应用缓存补值。托管的上下文压缩不自行降档。

## Alternatives considered

读取本机 Codex 缓存能解当前机的问题，但新装和自定义目录不可信；把 GPT 全部开六档会给四档和五档型号发错参数。

## Verification

对照三份公开资料生成的 46 个精确 ID，逐项核对工作台、配置校验和原生目录；合成未来型号检查最终请求体中 `xhigh` 与 `max` 不合并，并验证平台撤销、自动不指定、近似别名、账号隔离和目录往返。工作台与工具管理前端回归、Rust 库回归和 Clippy 在本地运行。未发送付费推理或安装替换用户应用。

## Consequences

自动时 `gpt-6-astra`、`gpt-6.2-astra` 与 `gpt-6.2-sol` 按该版官方数据默认 low；用户显式选择 medium 不被迁移为 low。全新协议档位或工具不认识的值仍需适配；冷启动可用内置资料，后续变化由同账号热目录提供。官方规格不等于每个渠道均已实测。
