# Agent Note: 保留已有真实数据并区分未知值

Status: implemented

## Problem

用户进一步要求有真实数据就显示。上一轮平台统计遇刷新失败会隐藏整个缓存；货币设置失败也连带隐藏请求/Token。现有余额将缺字段默认为零，本地统计查询出错与空结果混用，均可能误导。

## Existing capabilities and impact

复用平台summary、TanStack每账号/域名/范围缓存和原有本地查询。延伸[平台汇总](../feature/2026-11-17-platform-usage-summary.md)，替代其临时失败隐藏已有金额的做法，不新增账单估算或跨设备请求关联。现有 provider usage 的 keep-last-good 是其他查询协议；不把其余额推导与本模块混用。

## Decision

暂时网络失败保留同账号、同范围的最后结果并显示成功同步时刻；登录失效、切换账号/域名/日期范围时不混用。账号metadata刷新不清除统计缓存。平台summary有效但个别字段缺失时只将对应字段标为未知；货币配置读取失败不抹掉请求数/Token。余额响应缺值以nullable表达，UI不补零。本地汇总/趋势/表格保留已有行、显示上次读取时间；首次失败显示重试，不呈现虚假零或空表。

日历范围将起始日纳入缓存键，避免跨日把昨日的“今天”当今天；平台身份不一致或服务端401/403时清空同域名同账号的统计缓存，防止下次网络失败复活旧数据，其他账号不受影响。服务端 HTTP200 的 success:false 仅在 UserAuth 已添加 Auth-Version 时视为统计暂时不可用；无鉴权证据不复用旧结果。金额、计数和Token不跨请求时间段拼凑，若新结果只含部分字段，只显示该次实际返回的字段，不以旧字段冒充新值。

## Alternatives considered

- 每次失败都隐藏旧值：容易避免误看过期数据，但违背用户保留已有真实数据的目标。
- 刷新失败不提示：保持数字却让旧数据冒充新数据。
- 按最后已知余额推算消费：充值、其他设备和退款会破坏推算，仍用平台结算。

## Verification

新增反例先验证刷新失败、offline、同账号metadata刷新会丢掉缓存，以及缺失货币响应隐藏计数，再修复并通过。回归覆盖401后再次断网仍不复活旧数据（先红后绿）、同账号多范围缓存清除、其他账号隔离、统计业务暂时失败、单位API 503保留计数、nullable余额与零/负数、五个本地读取入口的错误与重试、已有供应商行保留。前端186文件1415项通过；最后缓存修复再跑10项专项通过；原生账号模块229项、Clippy、类型与格式检查通过。renderer构建通过，保留既有chunk体积和浏览器数据库陈旧警告。独立规格审查发现的两项问题修复后已复核关闭。

Chromium无头渲染6种状态（浅/深色、失败、退款、缓存过期、部分字段），1440×900及900×600均无横向溢出与页面错误。mock数据不代表线上已对账；本轮未读取个人令牌或发收费模型请求。预览浏览器、测试服务器与测试进程退出。

## Consequences

快照只保存在本次客户端查询缓存中，不承诺重启后离线查看。平台费用总计仍是全部设备；本机请求不映射为平台账单。旧版本缓存里曾补造的0无法事后识别，下一次真实账号同步后恢复nullable语义。
