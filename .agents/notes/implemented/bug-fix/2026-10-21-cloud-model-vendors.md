# Agent Note: 模型厂商跟随云端目录同步

Status: implemented

## Problem

客户端只按模型名的内置规则生成厂商，忽略定价目录的 vendors 和 vendor_id。云端增加或重命名厂商后，客户端仍显示旧名称或其他模型；新增规则需要重新发布客户端。

## Existing capabilities and impact

账号 sync_connection 已读取 /api/pricing、账号模型和各分组模型；ToolModelPicker 在工作台和工具管理复用同一目录与实时预检。扩展这条同步契约，不新增接口或独立目录查询。独立 ModelPicker 接受同一可选元数据，旧调用方仍兼容。

活跃笔记审计：[模型选择器层级](../feature/2026-10-02-model-picker-groups.md)、[工具分组级联](../feature/2026-10-20-tool-model-group-cascade.md)和[本地收藏](../feature/2026-10-04-model-picker-favorites.md)三篇部分重叠，保留交互、权限及存储边界并互链；安装连续性只要求刷新不卸载，继续适用。安装、诊断、线路和计费笔记不持有厂商归属决定，无需替换。

## Decision

账号快照增加默认空的 modelVendors，按精确模型名关联云端厂商 ID 和名称。只保留账号模型集合中的映射；云端厂商列表本身不授予模型可用性。选择器优先使用云端归属，稳定的 cloud:<id> 区分同名厂商；名称按原文展示，图标限本地资源。缺失映射继续按模型名兼容。

同步失败或旧接口未提供厂商目录时，只复用同地址、同账号快照中仍在新模型集合的归属；成功的空目录及删除映射必须生效。旧缓存反序列化默认空，不影响登录。模型排序、工具能力过滤、分组预检与保存时机保持。

模型和分组收藏保持原键；旧厂商收藏仅在当前云端分组全部属于同一已知旧分类时映射。用户操作厂商收藏时再将当前可完整解析的旧键转换为云端 ID，保留目录外收藏；部分目录仍有同一旧分类时保留旧键，避免取消收藏后又被兼容映射重新勾选。刷新不自动写偏好。打开厂商下拉框和分组模型弹层均复用原有刷新入口，正在进行的刷新由调用方去重。新增、改名与模型重新归属均随刷新更新弹层；首次补充云端归属时可将唯一旧分类映射到浏览中的新分支。

## Alternatives considered

- 只添加阿里百联硬编码最省改动，但下一次新增或改名仍需发布，不能解决目录同步缺口。
- 前端额外拉取公共定价目录可以减少 Rust 字段变更，但独立缓存会使账号目录、模型归属和失败恢复不一致；采用现有账号快照。
- 删除全部旧识别规则能统一来源，但旧缓存、缺失 vendor_id 和临时网络失败会让现有模型全部失去分类；保留缺失时的兼容路径。

## Verification

全量前端 149 个文件、987 项测试通过；随后补充部分目录收藏边界，相关 4 个文件 41 项回归通过。覆盖云端优先、同名厂商独立、目录权限交集、稳定 ID 改名、刷新后模型移除、旧收藏转换及工作台/工具管理两个 DSH 入口。Rust 全量测试通过（含 5 项新目录解析、缓存兼容与账号隔离回归），Clippy -D warnings、rustfmt、类型检查、格式、renderer 构建与版本一致性检查通过。

真实 App 壳使用隔离模拟 IPC 验证：阿里巴巴 → 阿里百联大模型的名称刷新、新增未知厂商无需重启出现、厂商/分组浏览不写配置、工作台模型叶子应用完整组合、工具管理保留草稿直到配置；目录刷新失败保留候选，搜索、ArrowRight 和 Esc 可用。1440×1000 浅色与 900×600 深色截图已复核，弹层不溢出。预览未使用真实账号、写入本机工具配置或调用收费模型；发布与镜像仍按既有工作流独立验证。

## Consequences

厂商更新不再依赖客户端发版，但快照增加每模型的厂商元数据；失败时只沿用同账号仍存在模型的旧关联，暂不能证明云端最新。旧缓存可正常加载并在下次打开选择器时补充归属；未提供映射的模型仍使用旧规则。部分目录的旧厂商收藏暂留原分类，完整映射后才转换。

云端名称或关联配置错误会原样显示，客户端不再擅自纠正归属。公共目录包含模型不代表当前账号拥有权限。模拟目录和浏览器检查不替代真实模型调用或用户设备网络验证。
