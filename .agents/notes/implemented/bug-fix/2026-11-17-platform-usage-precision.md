# Agent Note: 平台净消费保持金额精度与可核对口径

Status: implemented

## Problem

平台概览的 summary.quota 是扣费减退款，日志页 stat.quota 是扣费总额，直接比较会将退款差异误判为漏记。此前客户端为模仿网页显示，转为 Number 后取两位，并把微小正消费抬为 0.01，既丢精度又会夸大金额。用户要求有真实数据就显示且可核对。

## Existing capabilities and notes audit

[平台汇总](../../implemented/feature/2026-11-17-platform-usage-summary.md)继续负责本人只读接口、原生认证、同账号同范围缓存；本篇仅替代其“沿用网页 toFixed 和最低显示额”决定，保留旧取舍便于追溯。[数据可用性](../../implemented/bug-fix/2026-11-17-usage-data-availability.md)继续负责部分数据和失败快照，不重复实现。

本地 meta-api 的 model/dashboard_usage.go 已按 [start,end) 扫描保留的消费及退款记录，自动选组不影响历史额度；model/log.go 的日志统计只聚合消费且结束时间闭区间。无需另建聚合或修改结算、分组、令牌。网页概览当前两位显示仍可能与客户端精度不同，不声称所有页面展示完全一致。

## Decision

客户端命名为“净消费”，保持平台原生 Decimal 转出的字符串，渲染不经 Number、不截断、不抬最小金额。币种仅最少补两位，原始额度单位不补小数；千分位用 BigInt 的本地化格式，保留所有小数。单条信息提示交代全设备、退款按发生时间、半开时段、保留日志范围及网页日志扣费统计的区别。显示到秒，便于核对同一范围和快照。

以本地固定结算记录验证 API 汇总及客户端契约；夹具不使用客户数据、不调用收费模型，也不冒充线上验收。已有服务端协议足够，服务端仓库仅只读检查。

## Alternatives considered

- 完全照抄网页两位数易做但会把小额和退款舍入掉，放弃。
- 改服务端所有统计为净消费会破坏日志页原有扣费查询语义，且超出本轮客户端修复，不采用。
- 新增扣费/退款接口可提供分解，但需协调部署；已有净消费协议已满足当前客户端，不为显示修改增加依赖。

## Verification

金额反例先复现7项失败，修复后微小正负值、半分金额、超 JS 安全整数、真实零、额度单位均原精度显示。独立需求及规范审查发现缺币种仍默认美元；新增反例先失败，修复为缺失/null/非字符串/未知币种只隐藏金额、保留计数后，两路复核均无遗留发现。

复用 tests/fixtures/platform-usage-settlement.json：从本地 meta-api 仓库执行 `go run /path/to/client/tests/contracts/platform_usage_backend.go /path/to/client/tests/fixtures/platform-usage-settlement.json`，实际 self controller 在内存 SQLite 验证5种情形（扣费与退款、跨日退款、两日合并、小额、真实空时段）；包含自动组/备用组、任务差额不重复计请求、缓存不重复计 Token、半开时段及伪造其他用户查询参数隔离。相同夹具再经原生解析与真实卡片组件验证，不把预设 summary 冒充后端测试。

前端186文件1424项、原生账号模块231项通过；类型/格式、renderer构建与Clippy通过。浏览器模拟数据验证9种界面状态、1440×900/900×600/390×650、键盘 tooltip、极小与长金额，无横向溢出或页面错误。所有测试和预览进程已退出；保留既有大chunk和浏览器数据库陈旧警告。

后续在用户授权的 Apple Silicon Mac 运行当前源码候选，用户完成系统登录访问及日期选择后，原生“平台用量”展示真实历史整天结果。与用户确认的同账号、同期间网页概览截图比较，请求数和 Token 完全一致，净消费按网页两位小数显示也一致；候选保留更高精度。真实账号标识、账目数值、凭据及截图不纳入仓库夹具。已有工具配置与启动前本机备份一致，Core 原进程持续健康，未发起收费请求。

本地候选为 ad-hoc 签名，旧钥匙串恢复访问后可查询，但候选重启再次遇到权限限制。此结果不能证明正式签名升级的登录继承；原生候选测试结束后恢复已安装正式客户端，不更改钥匙串 ACL。正式同签名候选验证仍待发布准备阶段完成。

## Consequences

长金额需允许换行，缺币种时不能强行以美元显示。服务端保留期外记录不可恢复；网页日志页、不同筛选和不同查询时刻不能直接等同。原生 Decimal 为有限精度，非终止小数换算仍受其上限约束。

元衡客户端读取的仍是平台净消费，未修改报价、令牌路由或扣费逻辑。服务端仓库无本轮修改，不需要配套服务器部署。完整金额利于核对，但比原两位展示更长。真实账号的一个历史期间汇总已核对，不等于每条账目、全部期间或其他系统均已验收；正式安装包未发布。
