# Agent Note: Codex 旧字段清理与模型窗口一致性

Status: implemented

## Problem

Codex 提示忽略 disable_response_storage，而客户端多个模板仍生成它。只修改模板无法清理共用配置合并带回的旧字段。元衡模型目录统一写入 200000，同时主配置默认 921000，目录的 max_context_window 与 95% 有效比例使用户看到 190k。

## Decision

复用 Codex 配置准备、原子写入和模式切换快照流程。移除生成模板中的旧字段，并在写入边界仅清理同名顶层键；不修改嵌套自定义表、auth 或请求存储策略。

元衡自有目录按模型解析窗口：仅修复拥有权和四字段模板形状都吻合的旧 GPT 200k 默认，沿用现有 GPT 921000 产品默认与其他模型 200000 保守默认。该默认不代表上游能力认证。刷新及重新配置保留已有模型元数据；非元衡供应商及带自定义标记/标签的 200k 不迁移。目录使用逐模型窗口，移除元衡原先为 GPT 自动生成的全局默认；明确的非默认全局额度仍保留，并同步到当前选中模型。非 GPT 的 1M 设置也保留。

历史检索：help-drawer 仅描述说明入口，与本决策无关；[surface-mode-repair](../../implemented/bug-fix/2026-10-14-codex-surface-mode-repair.md) 涉及相同写入入口但保护的是拥有权与回滚，保持其边界。

## Alternatives considered

- 只删除本机字段、只把主配置改为 921000：改动小，但再次配置会复发，目录上限仍是 200k。
- 所有模型统一扩大为 921000：实现简单，但未知模型可能不支持，且覆盖明确自定义额度。
- 在现有写入边界清理并按模型生成目录：保留既有事务与隔离，代价是需覆盖旧数据和刷新兼容。

## Testing

Codex 相关 Rust 单元回归 626 项、provider_service 集成回归 16 项通过；前端配置/目录相关 49 项通过，类型检查通过。新增测试覆盖顶层字段清理幂等、嵌套同名字段保留、错误 TOML 拒绝、完整旧模板迁移、自定义 200k 与非 GPT 1M 保留、重配后的逐模型额度、CLI/Desktop 实际路由重复写入和 auth 字节不变。现有账号切换、失败回滚、共享配置和 MCP 回归一并执行；共享片段旧字段传播断言替换为正常 hide_agent_reasoning 传播与废弃键清理断言。测试使用隔离目录与随机端口本机代理，不修改真实用户配置、不发收费请求。

生产库 `cargo clippy --lib -- -D warnings`、修改文件的 Rust/前端格式检查与笔记校验通过。`cargo clippy --lib --tests -- -D warnings` 被 HEAD 已存在的两处测试告警阻断：core_diagnostics.rs 的 cloned_ref_to_slice_refs 和 secure_storage.rs 的 items_after_test_module；不扩展修改无关代码。没有进行 Windows 真机、已安装客户端或真实上游长上下文验收。

## Consequences

发布前全量验证：前端 145 文件/923 项通过；Rust 2498 项通过、3 项原有忽略。类型、全量前端格式、renderer 构建、版本公告和笔记校验通过；构建仅有原有包体积提示。使用本地隔离测试，不代表 Windows 真机或真实上游长请求成功。

旧托管目录没有数值来源标记，用户手工设置成与旧四字段模板完全一样的 GPT 200k 不能与旧默认区分；迁移只接受元衡自有记录和完整旧模板形状，新增来源标记避免重复猜测。旧 GPT 的 921000/1000000 顶层值也沿用既有默认迁移语义，不能推断它们的手工来源。有效窗口比例仍由目录模板决定，当前 95% 对应 874950，不承诺 UI 显示完整 921k。现有会话可能需要重开才能使用新目录；本地自动化不等于 Windows 真机或上游长上下文验收。

收益是旧字段不会因共享片段合并复发，目录上下限一致，刷新和重配保留已有模型额度。代价是保留旧默认的兼容识别逻辑；未来模型列表带权威容量字段时应替代产品默认，而不是继续按名称扩展容量表。只读检测不迁移实际文件，重新应用配置或切换元衡时复用已有写入事务。
