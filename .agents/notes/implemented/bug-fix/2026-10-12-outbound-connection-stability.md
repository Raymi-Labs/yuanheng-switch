# Agent Note: 出站连接池复用与安全连接诊断

Status: implemented

## Problem

Core 每秒重新加载设置并调用 apply_proxy，即使配置未变也重建 reqwest Client，丢弃空闲连接池。连接失败仅留下 error sending request，无法区分 DNS、代理隧道、TLS 与 TCP 错误。外部代理将目标误分为直连仍会失败，客户端不能承诺消除第三方网络故障。

## Existing capabilities and impact

复用 [全局 HTTP 客户端](../../../../src-tauri/src/proxy/http_client.rs)、[Core 刷新](../../../../src-tauri/src/core_daemon.rs)、[转发器](../../../../src-tauri/src/proxy/forwarder.rs) 和设置中的现有全局代理入口。影响所有共享 reqwest 客户端的调用；图片继续使用独立的禁止重放策略，Claude 原始头转发路径保持现状。已搜索活跃笔记，Claude 诊断笔记涉及独立请求阶段与本地记录，不持有全局连接池决定，无须合并或归档。现有 updater_proxy 只解析单个代理且 macOS 使用 scutil 子进程；本快照在每秒刷新路径直接读取原生系统配置，覆盖 reqwest 的 HTTP/HTTPS/NO_PROXY 语义，不修改独立更新器策略。

## Decision

将客户端和对应配置放入同一锁内原子替换。显式代理、环境变量、平台系统代理以及本机监听端口形成仅内存比较的配置快照；无变化时复用客户端，有变化时新建成功后替换，失败保留原状态。在现有一秒刷新周期内识别系统代理切换，不增加轮询线程。

沿最多 12 层错误源链提取有限的网络分类、标准 I/O 类型和 OS 错误编号，输出固定提示，不输出原始源链、URL、凭据或请求内容。连接失败与超时保持原有 HTTP 状态；不新增自动重试。补充用户排查文档，明确外部 DNS 与分流规则的处理边界。

## Alternatives considered

- 仅比较数据库中的代理 URL：实现最小，但 None 表示跟随系统代理，无法感知用户启动、关闭或切换系统代理，会使旧配置长时间停留。
- 周期性强制重建客户端：能重新读取系统代理，但定时丢池继续存在；采用与 reqwest 当前实际读取项一致的平台快照。
- 自动重试或内置公共 DNS、改写第三方代理规则：可能掩盖瞬时问题，但请求重放和网络路径变化影响计费、隐私及企业规则；保留用户网络控制权。
- 原样记录完整 source/debug 错误：排查信息最全，但底层错误可能带 URL 或凭据；使用有界白名单分类和 I/O 编号，未知原因明确保持未知。

## Verification

本机模拟 HTTP 代理确认连续刷新 20 次后仍复用同一 TCP 连接；无效配置更新不丢失旧池，换代理后新请求切换而正在等待的旧响应仍正常完成。配置快照测试覆盖平台值、环境值、监听端口和代理认证变化；真实拒绝连接与超时请求验证 502/504 及没有新增重放；嵌套 DNS、TLS、隧道和未知错误验证固定分类不输出敏感原文。

macOS 本地 2360 项 Rust 单元测试与 116 项集成测试通过（2 项既有忽略），899 项前端测试通过。Rust 格式、Clippy、类型、前端格式、版本公告、笔记检查、renderer 构建与 Core debug 构建通过。构建仅有既有前端体积和浏览器数据库提醒。三平台签名安装包及 GitHub 发布结果以对应发布流程实际结果为准。

## Consequences

配置稳定期间保留连接池，减少重复连接与每秒重复日志；系统代理变更仍在既有刷新周期内生效。平台快照需与当前 reqwest 系统代理读取语义保持一致，升级该依赖时应重新核对；Windows/Linux 原生代理切换仍需真机验证，跨平台编译与测试由 CI 执行。外部代理内部节点切换不需要重建 Client，外部分流错误也不会由本修复消除。未重启正在服务的 Core，不将构建或发布等同于本机已升级。分类为 unknown 时有意不保留未经审查的底层异常全文，需结合外部日志继续排查。
