# Agent Note: 自动依赖升级遵守已有兼容范围

Status: implemented

## Problem

Dependabot 把 61 项 Rust 依赖一起跨兼容范围升级，PR #68 的 CI #524 发生 34 个编译错误。数据库、加密、JavaScript 引擎与平台库迁移被混入例行更新，无法独立定位和验收。

现有能力是每周 Dependabot 分组更新、Cargo 清单约束与三平台 CI。检索活跃笔记中的 Dependabot 和依赖升级，仅命中媒体画廊笔记对检查结果的描述，与本决定无归属重叠。

## Decision

Cargo 的例行更新使用 lockfile-only，仅在现有 Cargo.toml 兼容约束内更新锁文件；跨约束升级保留为需要代码迁移和专门回归的维护工作。本次生成兼容范围内的最新锁文件，以通过三平台 CI 的更新替代失败的大批升级。npm 和 Actions 更新策略不在本次调整范围。

## Alternatives considered

- 一次适配 61 项升级能立即使用所有新版，但会同时改变数据库、加密与 JS 引擎契约，远超修复例行 CI 的必要范围。
- 完全关闭 Dependabot 可以减少通知，但会丢失兼容补丁和安全更新，因此保留自动更新及既有 CI。

## Consequences

例行更新继续接收兼容补丁，避免把需要改代码的 API 迁移混入一组更新。跨兼容范围的安全修复仍需人工评估和专门迁移，不能把 lockfile-only 理解为免维护。

Cargo 已按原始清单解析生成锁文件，清单没有改动；决策笔记结构检查通过。完整三平台编译与测试由本次 PR 的 CI 验证，合并前必须全部通过；锁文件解析不等于运行时正确。失败的旧批量更新在替代更新通过后关闭。
