# Agent Note: TRAE 本地模型缓存写入原生对照

Status: implemented

## Problem

用户要求实测直接修改本地缓存能否稳定配置TRAE，成功则复用其他Agent的工作台和工具管理入口。此前仅有只读结构/代码调查和原生表单验证，不能把资料中的缓存覆盖风险说成实测失败。

## Decision

遵循用户此前优先本机国内版、不再使用TRAE虚拟机的选择，在宿主已用于验收的官方国内版中，将变更范围隔离为两个model_list_map缓存的测试条目。实验使用正常退出、精确行0600备份、事务比较原值与条件更新；原登录、官方模型与非模型行不改，不覆盖整个数据库。

两轮原生对照均在启动刷新时丢失本地写入；该缓存写入路线不进入产品应用配置流程。统一工作台与其他Agent一致的目标保留，但本次未达到用户“没问题才接入”的条件，不能以新增独立辅助入口或伪成功状态代替自动配置。已存在的Responses真实原生文件能力仍有效，失败范围仅限直接编辑这两份缓存的持久化。

## Existing note review

- [原生接入提案](../../proposed/feature/2026-10-26-trae-native-integration.md)部分重叠，继续保留完整自动化范围；本篇补齐用户明确要求的缓存写入证据。
- [辅助配置](../../implemented/feature/2026-10-26-trae-official-custom-models.md)继续有效，只有新实验通过才替代其边界。
- [Responses修复](../../implemented/bug-fix/2026-10-28-trae-native-responses.md)为已知可用对照，不把高级参数回读异常等同缓存写入实验。

## Alternatives considered

- 继续只读静态分析：无变更风险，但不能回答用户要求的实际持久化/调用问题。
- 复制整个用户资料到新环境：可隔离目录，但复制官方登录凭据且新环境鉴权行为可能不同，不能作为无需登录的一键接入证明；不采用。
- 精确缓存行备份与受控修改：可使用真实已登录官方运行环境观察覆盖行为，代价是需先退出并明确恢复，采用。

## Consequences

获得了直接缓存写入不稳定的原生反例，不能再把此前静态判断混同实测，也不能声称所有本地存储路径均不可能。代价是需要进一步寻找真正的配置保存入口，并分别证明重开、刷新、实际推理和原配置保护；未确认前不发布自动写缓存功能。用户要求最终复用其他Agent工作台/工具卡，不另设孤立入口，后续统一实现以该目标为准。
